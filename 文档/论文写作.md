# 模块三 · 论文生成规范（DOCX 单版本）

面向**数学建模竞赛**论文生成与合规校验（默认 CUMCM 规则与母版）。目标：审题 → 建模 → 数值求解 → 论文写作 → 竞赛格式合规全链打通，论文在**结构、排版、表达**达"国奖优秀论文"水准。

## 官方模板（硬性输入）

内置母版：`文档/模板/2026数学建模国赛标准论文Word模板.docx`。直接读取该 `.docx`，无旧式 `.doc` 转换链路。

- 用途：论文生成基底，继承页面尺寸、章节层级、摘要布局、正文节奏、图表与附录组织。
- 生成链路：进赛题目录后先 `pf.new_project_document(PROJECT_ROOT)` 复制为 `论文模板.docx`。模板只提供标题层级、字体、段落、页面、题注样式；论文标题和章节按赛题增删改，不要求保留模板原标题。
- 交付链路：`pf.save_document(..., filename="完整论文.docx")` 从模板副本生成正式稿并改名；母版与模板副本均不覆盖。
- 边界：文档须从母版或其未修改副本起步，保证样式来源可靠；进入文档对象后可按赛题改标题与内容。项目母版不覆盖；`论文模板.docx` 在终稿交付后删除。
- 正文换行：`pf.body()` 把源文本换行合并为空格或中文连续文本；正文禁止强制换行。附录只留核心代码片段。绕过入口写入的强制换行被结构校验拒交付。

论文手把 `results/` 真实运行结果（清单 `results/run_manifest.json`）写入 `论文模板.docx`，生成经校验的 DOCX；提交 PDF 只从最终 DOCX 导出。生成与校验不依赖 Word/LibreOffice，不回退空白文档。无实际渲染页数时按内容等效页数下限核验。公式全部 Word 原生 OMML，图表全部真实运行结果。`save_document` 在 DOCX 发布前从同一内容快照自动导出 `完整论文.tex`（LaTeX 源码版，映射规则见 `文档/样式统一规定.md` §十二；不编译、不留 `.aux`/`.log` 构建文件）。

## 〇、论文铁律（不可违反）

1. **原创底线**：可吸收优秀论文方法经验，但须结合本题数据、目标、约束重新设计、独立实现、真实运行验证；不得复制原文、公式写法、代码、数字、创新表述。可联网查背景、数据、文献辅助理解查证，**绝不抄袭**网络论文/题解内容。
2. **数值可复现**：每个结论有可运行代码支撑；关键结果用"两种独立方法"交叉验证。
3. **审题先于动手**：先用 `fitz`(PyMuPDF) 提取赛题 PDF 全文（中文 PDF 别用 PyPDF2），逐条列已知条件、给定表格、参数、各问所问。
4. **图必须自己插进论文**：`results/图片/` 每张登记图都用 `pf.add_figure(doc, path, "图N …")` 插到对应小节，否则 `save_document` 拒存。禁止图只留目录。
5. **从开篇按终稿预算写**：摘要、正文、附录一开始按"项目交付下限表"规划；不能先写短稿再调版式补页。
6. **写不满就扩、不达标不交**：论文只以 `pf.save_document(...)` 交付。该函数强制纯黑并跑 `validate_paper_structure`；任一致命错误（页数/字数/图/表/公式不足、非黑字体、禁用词）**拒绝保存**。

## 一、国奖论文共性结构模板（按此骨架生成）
```text
摘要（单独第 1 页，摘要与关键词合计不超过一页）
一、问题重述        ← 1.1 问题背景 / 1.2 问题提出（逐问列出各小问要求）
二、问题分析        ← 2.1 问题一分析 / 2.2 问题二分析 …每问一小节；
                       必要时在节末放一张"总体研究思路/技术路线"流程图（图1）
三、模型假设        ← 用"假设1：内容。依据：..."逐条编号，短句为主，不写大段解释
四、符号说明        ← 三线表（表1：主要符号说明）： 符号(正体) | 含义 | 单位；表前最多一句引入，表后不写说明段
五、模型的建立与求解  ← 可按问题、模型模块、算法链或工况分 5.1 / 5.2 / 5.3 …
                       三级标题必须随内容命名，如"系统状态空间与事件驱动模型""综合优先级评分""随机故障滚动重调度"
                       不把 5.x.1/5.x.2/5.x.3 写死为"模型建立/模型求解/结果分析"
                       每个分支都要写清模型或算法、求解证据、结果解释与合理性分析
六、模型检验与分析   ← 6.1 数值验证与交叉检验，6.2 灵敏度分析（关键参数±变动看趋势）
                       6.3 误差/稳健性分析
七、模型评价与改进   ← 7.1 模型优点 / 7.2 模型缺点 / 7.3 改进与推广
AI 工具使用声明    ← 参考文献**之前**，按《文档/合规检查清单.md 附录 A》第三条二选一固定文案
参考文献            ← 按 [1][2]… 编号，正文用"式/文献[1]"标注
附录                ← 附录A 支撑材料（源码/数据文件清单，由 run_manifest 自动生成）+ 附录B/C/D… 各小问核心代码
```

- 一级标题用"一、二、三"中文序号；二级 1.x/2.x；三级 1.m.n/2.m.n，全文统一。
- 摘要：浓缩问题、方法、核心结果、结论；不含图表，自包含。
- 正文每节**有内容**：分析深入、推导充分、参数解释清楚；每个 5.x 分支在第五章内完成结果解释与合理性分析，小标题按内容自拟，不强制 `5.x.3 结果分析`。
- 动笔前按 **§4.0 题型画像判定** 判每个子问题的数学画像（几何/机理、优化/决策、数据/预测、评价/分类、图论/网络、仿真/不确定性），据此调建模重心、论文结构、图表职责；不按 A/B/C 题号硬套模型。
- 附录两层：**附录A 支撑材料**（由 `run_manifest.json` 的 `source_scripts` + 数据文件自动生成清单，非空赛题必有实质内容）+ **附录B/C/D… 各小问核心代码**（按 Q<序号> 聚类，每题区下挂 heading3 文件名 + 带行号等宽代码表，表前补居中"表N：xxx核心代码"题注）。代码按 `source_scripts` 反推被结果引用的 `code/*.py`，公共模块一并入录；manifest 缺失时退回 `code/Q*.py`。须调 `pf.append_code_files(project_root)` 渲染，禁文字描述替代；不放论文生成脚本、临时脚本、无关说明。纯理论小问附录B… 可空，附录A 段保留。

## 二、各节内容预算（防"6 页骨架型"短文的硬下限）

**完整论文与骨架短文的分水岭。** 每节写作阶段按项目交付下限表预算，写不满就补建模推导、实验分析、结果讨论，**严禁**调大字体、加空白、凑页数。交付前重开暂存 DOCX 核对结构、内容、产物关联指标。

### 内容预算表

| 章节 | 建议字数 | 建议页数 | 详细写法 |
|---|---:|---:|---|
| **摘要（含关键词）** | 700-800 | 1 | 见 `知识库/写作增强/摘要写作范式.md`（唯一权威） |
| 问题重述 | 800-1000 | 0.5-1 | — |
| 问题分析 | 1000-1200 | 1.5 | — |
| 模型假设 | 300-600 | 0.5 以内 | — |
| 符号说明 | 表格为主，不按正文凑字 | 0.3-0.5 | — |
| 模型建立（5.x） | 5000-6000 | 8-10 | — |
| 灵敏度/检验 | 1300-1500 | 3-4 | — |
| 优缺点/推广 | 800-1000 | 1 | — |
| 参考文献 | 300 | 0.5 | — |
| 附录 | 按源码实际长度 | 不设项目自定义行数上限 | — |
| **合计** | 按项目交付下限表 | 按项目交付下限表 | — |

写作工具提供 `pf.preflight_check(outline)`：正文生成前查 5.x 分问、每问通俗解读、图/表/公式规划、摘要独占首页、字数预算。写作中调 `pf.emit_progress(doc, "writing")`，日志实时给字数、图数、缺口。

生成阶段硬拦截身份/痕迹词：`智能体`、`skill`、`WorkBuddy`、`合并`、`融合两`、`参考解` 等，命中中止写入，不自动改写；口语主语词（我们/本文/该模型）不硬拦，动笔前先读 `知识库/写作增强/去AI味指南.md` 自觉规避；AI 合规标注与参考文献登记不拦截，详见 `文档/合规检查清单.md 附录 A`。

| 章节 | 最低篇幅 | 必须包含（缺一不可） |
|---|---|---|
| **摘要（含关键词）** | 700–800 字 | 详细写法见 `知识库/写作增强/摘要写作范式.md`（唯一权威：四块内容/篇幅版式/句式模板/题型侧重/核对清单） |
| 一、问题重述 | 0.5–1 页（半页到一页即可） | 1.1 问题背景 / 1.2 问题提出；逐条列出已知条件、给定表格/参数、各小问分别问什么。**红线**：不得剧透符号说明与模型分析内容；不得用「就X而言」「从Y角度」「综上可抽象为…」等套话反复铺陈同一信息；字数控制在半页到一页，宁短勿冗 |
| 二、问题分析 | 1–1.5 页（结构须平衡，禁止一头沉） | 2.x 每小问单独一节分析思路；多问存在数据流、决策链或递进关系时，在问题分析中优先放一张本题化的总体研究思路/技术路线流程图。**平衡红线**：导论段只写物理本质、边界条件和流程图引入（≤2 段），不得把整章篇幅堆在导论；2.1/2.2/2.3 每节须充实到 2–3 段（问题本质 / 方法思路 / 与前后问的衔接关系），不得每节只写 1 句；导论与子节篇幅应大致均衡 |
| 三、模型假设 | 半页以内为宜 | "假设1：/假设2：…"逐条编号，按题目需要一般 6-12 条；单条一两句，写清内容与依据即可，不扩写背景和意义 |
| 四、符号说明 | 三线表 ≥12 行（表1：主要符号说明） | 符号(正体)｜含义｜单位，整表内容居中、符号不跨行；表前最多一句引入，表后不写任何说明段；符号说明与数学公式无关，禁止用公式/equation 注入 |
| 五、建模与求解 | 按项目交付下限表规划 | 5.x 可按子问题、通用模型、算法模块、工况或验证回填组织；三级标题必须内容化命名，每个分支都要写清模型或算法、求解证据和结果解释；不得另起与第五章并列的一级“结果分析”章节 |
| 六、模型检验与分析 | 按题目需要 | 从数值一致性、可行性、误差、极限情形、基线、灵敏度或稳健性中选择与本题相称的检查，不强制同时使用所有项目 |
| 七、模型评价与改进 | 篇幅服从正文总字数下限，不另设页数硬限 | 7.1 优点 / 7.2 缺点 / 7.3 改进方向与推广，不空泛 |
| 参考文献 | 真实且正文对应 | 正文引用处标注 [1][2]…，与文末一一对应 |
| 附录 | 按源码实际长度 | 不设项目自定义行数上限 |

> 页数、字数、图表、公式、参考文献阈值均见文末"项目交付下限表"，不重复定义。
>
> **页数接近下限属"擦边"，务必留缓冲**：从问题分析和章节预算阶段就按表组织；每问预留机理分析、极限情形、量纲检验、参数推广、误差来源分解篇幅。完稿后调格式不计入内容补充。

流程图只在有真实验证链、反馈链、改进链时放；节点写本题数据、指标、阈值、决策，不画"输入—处理—输出"空流程图。

## 三、排版格式细则（对齐国奖范式）

- **页面**：A4，四边 ≥2.5 cm，左侧装订；首页摘要、无目录；正文遵守当届上限，附录不计入。
- **版式数值**：字体、字号、行距、缩进、间距、页边距、图片命名与防 Word 重排数值**唯一权威 `文档/样式统一规定.md`**（正文固定 18 磅；公式段 1.5 倍、图片段 1.25 倍——固定值裁剪公式与图片，`_clipped_object_issues` 硬闸门拒存）。
- **字体字号**：严格遵循母版样式定义；`validate_paper_structure()` 逐段核验。**全文字体黑色 RGB(0,0,0)**：每个 run 显式写黑，禁蓝标题、彩超链、灰表格——`paper_format.set_run_font` 默认写黑；交付前 `check_black_fonts` 按**有效颜色**口径扫描（run 显式色 → 字符样式链 → 段落样式链），覆盖正文、表格、文本框、超链接、页眉页脚；任何非黑显示色 >0 即致命拒存。
- **正文文件名禁用**：正文（不含附录、参考文献）不得出现任何文件名；引用代码/数据只用"脚本""数据文件""结果表"泛指，具体文件名只进附录或支撑材料清单。
- **题注**：用"图表排序"样式；图题图下、表题表上。
- **正文边界**：参考文献之前为正文；参考文献与附录不算正文，不入篇幅、图表计数与结构检验。**附录图表不做结构检验**（计数、题注连续性、正文引用校验截至参考文献/附录起），附录表用闭合方框表。
- **公式不可置图**：公式一律 Word 原生 OMML `m:oMath`，不得图片呈现（符号说明表符号除外）。
- **摘要**：单独第 1 页；含标题与关键词；关键词 4–6 个；摘要与关键词合计不超一页；不用英文翻译。按赛题对象、方法、数值结果、检验边界组织，避免固定开头和填空句式；**详见 `知识库/写作增强/摘要写作范式.md`（唯一权威）**。
- **页码**：电子版第 1 页到末页页脚居中 PAGE 域，阿拉伯数字从 1 连续。
- **篇幅与图数下限（未达标禁交）**：写作按文末下限表规划；交付前跑 `validate_paper_structure()` 并对保存后 DOCX 再校验。不足优先补推导、实验分析、结果讨论，禁凑页、扩字体、加空白。
> **图表规范三层架构**：机器闸门 `文档/图片闸门配置与绘图规范.md`（H/W/D 三层，validator 直连）；写作指导本节；正向范式 `知识库/写作增强/七轮自审框架.md` 附录（10 条正向模式对照，模式 3）。三层互补不重复。

- **图文分布**：图表按论证需要安排；结果图放首次解释处，后文只引图号。禁凑数硬塞、禁同图换题注重复使用。
- **出图字体与正文一致**：代码生成图片（流程图、曲线、热图、收敛图等）的中文标签、标题、图例、坐标名字体字号颜色遵循母版样式；中文标签宋体、字号 ≥11pt、dpi ≥300；图内文字不遮挡、不与图形重叠。
- **模型假设**：只列与模型、数据、求解边界直接相关的条件；"假设N：内容。依据：题面/附件/数据/必要简化。"短句写法。禁长段解释、研究意义、口号式合理性凑篇幅。
- **模型评价篇幅**：集中写优点、局限、改进方向，不重复正文推导与结果；不设硬页限，由正文总字数下限（`CUMCM_MIN_BODY_UNITS=12222`）统一约束（D4「不空泛」）。
- **前置章节排版**："问题重述"与"问题分析"连续组织，不强制分页；问题分析紧接问题重述。
- **图**：标题图下居中"图N：xxx"（如"图2：同心鼓系统三维拓扑图"，冒号写法全文统一）；编号全局连续无缺号；每图服务论证。**统一用 `pf.add_figure(doc, path, "图N …")`**（图片与题注一次完成，题注须"图N"开头，否则编号校验判缺失）；禁裸 `add_picture`；登记清单每张图必须进正文对应小节，图数不一致 `save_document` 拒收。
- **结果对应**：摘要、结论、主图题注的关键结论必须能在当前批次结果清单及来源文件找到，并在对应小节说明用途（登记以 `results/run_manifest.json` 为准）；禁编造数字、禁未运行图表。
- **表**：标题表上居中"表N：xxx"（如"表1：主要符号说明"）；**正文**表均三线表，表头黑体、正文宋体、数字右对齐，编号连续。**三线表必须完整三条线：顶线+表头分隔线+底线**——两线表、网格表不合规；表头分隔线经首行单元格 `tcBorders/bottom=single` 实现，单行表豁免。**附录表禁三线表，一律闭合方框表（四边 left/right/top/bottom=single、无内部竖线 insideV=nil），H10 闸门强制；正文方框表、附录三线表均不合规。**符号说明表特例：整表内容居中、符号正体、不跨行，与数学公式无关，禁公式/equation 注入。
- **公式分布**：除总量下限外，**标题含"建立/建模"的小节必须 ≥1 个 oMath 公式**——建模无数理表达式不成立；空缺由 `_model_section_formula_issues` 判致命。
- **摘要数字密度**：数值支撑结论而非堆砌。摘要（含关键词）数字字符占比 **>18% 致命拒存，>10% 预警**；保留关键量值，其余移正文。
- **公式**：Word 原生 OMML，**不用图片**！源稿先记可直接转 LaTeX 的单行写法，最终写入可编辑 OMML。每式独占一段一行居中，公式 1.5 倍行距，与上下文间距 1.5 倍正文行距（27 pt）；公式链按"定义/物理或统计依据 → 代入、联立、化简或积分推导 → 结论/用途"展开，不能只丢最终式。上一段给用途，下一段解释推导结果；不自动生成编号。需右侧编号时显式调 `pf.equation(doc, latex, number="(1)")`。
- **匿名**：全文不得出现学校、赛区、姓名等身份信息。

## 四、优秀论文写法（按题目适配）

除格式合规外，优先写清真正解决本题难点的建模选择。同组变量、同求解对象、两法互验、灵敏度分析、全情景计算都是按需工具；完整源码与真实结果始终保留。

### 4.0 题型画像判定

> **动笔前先按本节判定每个子问题的数学画像**，据此调建模重心、论文结构、图表职责；不按 A/B/C 题号硬套模型。一道题可含多个画像；先逐问判断，再定模型、公式、图表、检查方式。

#### 4.0.1 产出画像速查

| 画像 | 主要产出 | 写作重心 | 优先图表 |
|---|---|---|---|
| **几何/机理** | 方程、轨迹、场、参数、物理解释 | 假设、变量、边界、逐步推导、量纲、极限情形 | 几何图、演化曲线、模型-解析/实测对比 |
| **优化/决策** | 可行方案、排程、路径、资源分配 | 决策变量、目标、约束、求解步骤、可行性 | 技术路线、方案对比表、路线图、收敛/排程图 |
| **数据/预测** | 预测值、趋势、误差/区间 | 数据质量、特征/变量、训练检验划分、误差解释 | 数据概览、趋势图、预测对比、残差图 |
| **评价/分类** | 得分、排名、类别、异常 | 指标方向、权重/分类规则、分组解释、稳定性 | 指标表、排名图、分布图、混淆矩阵/聚类图 |
| **图论/网络** | 路径、流量、匹配、连通、覆盖 | 节点边抽象、边权、路径约束、可行性 | 网络图、路线图、覆盖图、流量/匹配表 |
| **仿真/不确定性** | 场景结果、分布、风险/区间 | 随机设定、场景构造、试验次数、统计摘要、边界 | 场景对比、分布图、置信区间、风险曲线 |

#### 4.0.2 公式写法（每式独占一段，显式编号）

1. **定义**：对象、变量、参数、单位，说明对应题目何量
2. **依据**：物理定律/统计定义/目标/约束的原始关系
3. **推导**：代入/联立/消元/离散化/积分/归一化 → 每步一式
4. **结论**：最终式用途、可求解变量、适用条件
```text
定义：设入射方向 u=(u_x,u_y)，法向量 n=(n_x,n_y)，||n||_2=1。
依据：反射方向等入射方向关于法向量的镜像。
LaTeX：r = u - 2(u·n)n
推导：分解 u，法向分量为 (u·n)n，反射后变号。
结论：r 给出反射方向，后续与目标平面联立即可求交点。
```

> 严禁：把"定义/推导/结论"塞一行、关键公式放附录或图片、手写编号文字。

#### 4.0.3 图表分布原则

- 多小问/数据流/决策链 → 必放本题化流程图/技术路线图（节点写具体变量/动作/输出，禁空泛"分析数据—建立模型—得到结果"）
- 图表按论证需用；后续引用已有图号，不重复插图；纯解析小问不硬塞
- 图表按正文出现顺序分散到对应小节；禁章末堆图、禁连续≥3视觉对象无解释段
- 图题说明"读者该看什么"；精确数值用表，趋势/结构/对比/过程用图

#### 4.0.4 检查方式按题目选择

| 题型 | 必选检查 |
|---|---|
| 几何/机理 | 量纲、边界条件、极限情形、解析解或实测对比 |
| 优化/决策 | 约束满足、方案可实施性、简单基线、目标变化 |
| 数据/预测 | 留出集/交叉验证、误差指标、残差、失败样本 |
| 评价/分类 | 指标方向、权重变化、类别平衡、排名/聚类稳定性 |
| 图论/网络 | 节点边完整性、路径可达性、边权解释、容量约束 |
| 仿真/不确定性 | 随机种子、试验次数、分布摘要、区间、场景边界 |

> 双模型/灵敏度/鲁棒性/显著性/全情景计算是按需工具，非统一硬指标。未运行的检查不写进论文；不适用的说明原因。

#### 4.0.5 优秀论文参考边界

案例库仅供学习：问题抽象、推导节奏、图表职责、结果解释。检索结果只给候选方向；新题必须**重新定义变量/参数/约束，独立实现并运行**。**不得复制**原文文字、公式、代码、数字、模型命名、创新表述。

---

### 4.1 建模组织：让各问有关系但不强行统一

- 小问间确有输入输出关系 → 一条主线贯穿；各问对象不同 → 分别建模，问题分析写清边界，不为统一结构强行拼接。
- 先画问题分解与结果依赖：每个 5.x 分支能回答"解决哪个子问题、用哪个输入、输出什么、为后续哪步供什么"；无真实依赖不强行串联。
- 高级方法用在"刀刃"上并说明为何合适：姿态用**四元数**（避万向锁）；运动方程用**四阶 Runge-Kutta** 积分；误差校正用一阶傅里叶分解 `T_i = T0+ΔTz+a·cosφ_i+b·sinφ_i` 解耦"整体升降 ↔ 两向倾斜"；拉力分配用余弦规律 `T_i = T0 + A·cos(φ_i−ψ_c)` 或力矩逆解。
- 简化必须有依据：**小角度假设要先被"完整模型"验证过**才敢用。

### 4.2 求解检查：选择与问题相称的核验方式

- 关键数值存在可比方法时用两套独立方法交叉检查；几何/机理题用极限情形或量纲检查，优化题用可行性和基线检查，数据题用留出集、交叉验证或残差检查。
- 模型/算法选择写清本题适配理由、合理替代方案及取舍；无合理替代时说明"为何不需强行比较"，不为形式制造第二模型。
- 求解过程记录实际关键参数、停止条件、收敛/可行性证据、失败处理；无运行记录的过程不得补写。
- 主动纠正常见公式符号错误（如碰撞反弹公式用 `(eM−m)`，避免 `(m−eM)`），并说明修正理由。
- 对确实影响结论的参数做灵敏度或扰动分析；参数不敏感、无扰动含义或计算规模不允许时说明原因，改用更合适检查。
- 引入真实约束体现工程思维：量化"人体反应时延约 0.2 s"对纠偏残余误差的影响，给出"分 2–3 次渐进纠偏收敛"的可操作结论。

### 4.3 表达创新：让评委一眼看懂巧思

- 多问递进时，问题分析开篇或节末放总体研究思路/技术路线流程图，节点写本题变量、动作、输出；独立小问不强行画空流程图。
- 第五章标题内容驱动：按"通用模型、算法模块、工况分支、子问题"组织；机械套用 `模型建立 → 模型求解 → 结果分析` 会僵化。图片放首次解释其信息处，后续引用已有图号，不重复插入。
- 图分层服务论证：几何示意图、结果曲线、反馈/纠偏流程图、倾斜轴方位图各司其职。
- 题目存在反馈、迭代、动态纠偏时，把误差作为状态变量并报告校正前后变化；无此类结构时改写为普通误差分析或稳健性说明。
- 模型评价写具体：优点指向变量少、约束完整、两法互验、运行时间可控等事实；缺点写清依赖理想参数、忽略绳弹性等边界；改进落到换优化算法、加阻尼项、推广 n 人 m 鼓等具体动作。

### 4.4 严谨性创新：主动堵上可被挑刺处

- 合理性检验：结果与物理直觉/极限情形比对（等幅稳态、最小能耗临界等）。
- 误差与不确定性：给数值量级估计，说明可信区间。
- 文献与数据：引用通用教材/手册并正文标注；不杜撰数据。

### 4.5 完整性创新：超出题目要求的加分项

- 题目给的所有情景都算全（如 9 种发力情形全列倾角，只算 1 个不符合全情景要求）。
- 附录只放各小问最终核心代码，源码与本次运行结果严格一致。
- 讨论推广价值：模型可迁移到哪些同类问题（多体协同、柔性绳、不同几何体）。

### 7.1 证据纪律（从产物出发，核心原则不变）

写作只认产物，不认感觉。正文、摘要、附录、结论里每句判断都要能在结果文件、图表、公式推导、脚本输出或稳健性检查里找到依据。

**能写**：问题解析、最终方法说明、人工决策台账、数据画像、脚本、冻结数值、图表、稳健性报告、方案包、质检笔记；每章写"做了什么/为什么这样做/结果说明什么/边界在哪"；摘要写问题/方法/主要结果/检验边界；问题重述只写题目已给出的背景/目标/子问题/产出/约束。

**不能写**：无证据的数据/数值/参考文献/图表/参数/实验结论/模型性能声称；无基线不写"更优"；无稳健性不写"全局稳健/鲁棒性强"；无结果支撑不写空泛结论。

**SPSS 等人工工具结果**：一等公民，与 Python 结果平级；登记链条（SPSS → `results/数据/spss_outputs.json` → `run_manifest.manual_stats` → 逐字核对）与 gate 规则见 `SKILL.md` 铁律 8（唯一权威），此处不重复。

**每章落点**：摘要(问题+方法+数值+边界) → 问题分析(任务类型/依赖/拆解) → 假设(必要性/对应关系) → 符号说明(定义先行/注单位) → 模型建立(契合理由/基线/输出) → 模型求解(算法/过程/脚本/输出) → 结果分析(解释真实结果/不越界) → 稳健性/灵敏度(稳定/脆弱/边界) → 优缺点(局限落假设/数据/方法/验证) → 结论(回子问题/不增新声称)。

**句子检查六问**：回应哪子问题？由哪产物支撑？是否数值声称？数值在结果文件里？需基线/稳健性？措辞是否超证据？

**引用/图表/结论闭环**：参考文献两层核对（书目信息/观点证据）；`citation_ready` 只过书目层；图表区分观察/原因/结论；摘要内容必在正文与结果文件对应；无产物支撑不写。

**交付原则**：有证据弱声称 > 无证据强声称；技术语气克制、句子短、主语具体、结论留边界。

## 八、赛题详解与结果分析规范

> 分析内容（题目理解、问题拆解、思路、模型设计论证、结果解释、创新点）**直接组织进论文正文对应章节**（问题重述 / 问题分析 / 模型建立 / 结果分析 / 结论），并沉淀进 `results/论文评审与分析.md` 的修改闭环；**不单独产出 `results/赛题详解与结果分析.md` 或任何独立分析报告、结果分析、阶段小结文件**。结果清单以 `results/run_manifest.json` 为唯一登记。

### 8.1 选模前置：案例检索

选模前必须跑案例检索工具，按宽题目画像、方法和约束匹配"案例五维方法卡"。画像只扩大参考范围，不按 A/B/C 题号分流：

```bash
python tools/project_ops/case_retrieval.py --query-file <赛题 PDF> --query-file <赛题 DOCX> --top-k 5
```

工具输出参考块**仅进会话上下文**供本题化设计，不落盘任何检索报告。不得只凭案例标题或原始 PDF 直接套用模型。

### 8.2 案例参考转化规则

会话上下文保留每个入选案例四项信息（案例卡路径、题目画像与匹配依据、可迁移方法、本题化候选），按需写入论文正文模型设计小节。候选方案须经以下转化才能进模型方案：

1. **案例经验**：案例解决了什么结构问题，用什么模型族、约束表达、验证方式。
2. **本题差异**：本赛题的数据、目标、约束、规模、不确定性与案例有何不同。
3. **本题候选创新**：只提出可由本题数据验证的改进，如现实约束量化、目标函数扩展、动态/鲁棒情景、基线对比、验证闭环。
4. **核验计划**：明确用什么数值检查、基线、对照实验、灵敏度分析、极限情形或鲁棒性检查确认候选方案适用。非每类题都须同时使用。

> 案例卡 `创新信号` 是候选方向，非原论文真实创新结论；低质量案例只作待复核线索。案例卡不得进论文参考文献，真实引用必须来自 `tools/paper_search/` 的 `citation_ready=true` 结果；论文具体观点仍须原文证据，不得凭标题或摘要推断。

### 8.3 写作总则

- 像高水平建模队员做的**内部技术笔记 + 方案论证**，逻辑严密、推导充分、可读。
- 每条结论能回到实际数据、推导、实验或题目条件，禁空话与"显然"；不要求逐句证据台账。"优于、显著、鲁棒、因果、创新"等强结论必须补可比实验、推导、边界检查或真实文献依据；证据不足收窄措辞。
- 模型选择讲清"为什么适配本题、有哪些合理候选、最终为何取舍"，禁直接堆公式；无合理候选不强行制造比较。

### 8.4 七节强制结构

#### 1. 题目理解
- **研究背景**：题目来自什么现实场景，解决什么科学与工程问题。
- **核心问题**：一句话点破数学本质（优化 / 预测 / 评价 / 分类 / 仿真…）。
- **数学本质**：文字题翻译成数学对象（变量、约束、目标、已知/未知）。

#### 2. 问题拆解
逐问分析（几个子问题列几个）：
- **问题目标**：这一问产出什么。
- **输入数据**：用什么数据 / 需要哪些量。
- **输出目标**：交付什么结果（数值、曲线、方案、排序…）。
- **难点分析**：卡点在哪（数据缺失、非线性、多目标、不确定…）。

#### 3. 整体解题思路
给完整路线（箭头串联）：

```text
数据处理 → 模型建立 → 算法求解 → 结果分析 → 模型优化
```

每一环写清"做什么、为什么这样排"。标明各环节输入、输出、证据来源，避免"数据—模型—结果"空流程。

#### 4. 模型设计

> 选型遵循 `文档/论文写作.md §四`（题型画像）：先判子问题产出和数学结构，再从相容方法族选主模型。确有可比候选才做基线或多方案比较；不强制跨模型族挑战者。

对每个候选/最终模型：
- **为什么选它**：适配题目哪点。
- **模型思想**：直觉与机理。
- **数学表达**：核心公式用可直接转 LaTeX 的单行写法记录，按"定义/依据 → 推导 → 结论或用途"展开；变量先定义后使用。
- **变量定义**：表格化符号说明。
- **假设条件**：必要假设 vs 简化假设，各写理由与影响。
- **求解方法**：算法名 + 步骤 + 关键超参；记录真实参数依据、停止条件、收敛或可行性检查，不补写未经运行的"调试过程"。

#### 5. 最优方案说明
- 明确**最终采用哪个方案**。
- 有合理候选时解释最终方案为何适配本题，同数据、同指标、同约束下说明选择依据；无合理替代不强行多模型对比。准确性、稳定性、可解释性、本题化改进只写有证据部分。

#### 6. 结果分析

> 所有数值结论来自 `results/` 真实运行产物；按题目需要做误差、可行性、极限情形、基线或参数检查，不要求所有题用同一证据模板。

**必须结合真实运行结果**（数值来自 `results/`，不得编造）：
- **图表解释**：每图说明展示对象、关键趋势或差异、可能原因、对本问的作用；不得只写"由图可知"。
- **参数分析**：关键参数敏感性、鲁棒性。
- **模型检查**：按题目类型选误差指标、交叉验证、对照实验、基线比较、极限情形或可行性检查。
- **证据边界**：明确结果适用数据、参数、场景范围；单次实验不成普遍规律，相关性不直接写因果。

#### 7. 创新点总结
- 只写**真实创新**：新方法、新组合、新视角、新数据处理。
- 禁把普通步骤包装成创新。每条创新点写清"新在哪、带来什么提升"，给对应结果或推导；无实证提升只写"本题化处理"或"方案特点"。

## 十、优秀论文学习与经验迁移

> 来源：`知识库/优秀论文案例/`（优秀论文库）与 `知识库/方法库/`（方法库）。**允许迁移算法思想和建模经验，但必须结合本题重构、独立实现、重新验证；绝不抄内容。**

### 10.1 学什么（六类可迁移经验）

1. **问题分析方式**：如何把模糊赛题拆成可建模子问题
2. **模型递进方式**：从简单基线到复杂模型的演进逻辑
3. **数学表达方式**：公式组织、符号约定、推导节奏
4. **结果解释方式**：把数字讲成"有说服力的结论"
5. **图表设计方式**：选图、标注、配色最清晰
6. **论文排版规范**：结构、篇幅、匿名、附录处理

### 10.2 禁止什么（红线）

- 复制文字、公式、代码、具体数字、原论文创新表述——任何形式都不行；算法思想可本题化迁移
- 直接复用某篇优秀论文"整体框架"当自己论文
- 把库中文献当真实引用塞进新论文（未真正读过不得引用）

### 10.3 如何形成经验库

- 用户上传优秀论文 PDF → `tools/paperingest/` 自动抽取文本层或 OCR 扫描页 → 逐篇生成同名五维方法卡（原文证据位置、排版逻辑、模型假设、方法命中、创新信号、图表组织）。新赛题用 `python tools/project_ops/case_retrieval.py --query-file <赛题 PDF> --query-file <赛题 DOCX> --top-k 5` 合并两个版本，PDF/DOCX 不启用 OCR；DOCX 中 WMF/EMF、VML、OLE 对象另由附件提取器清单化，对全部 Markdown 卡片按题型、方法、约束排序，不维护单独索引
- 全库蒸馏：`python tools/paperingest/distill.py --raw <PDF目录>` 跨论文统计章节骨架出现率与顺序、创新点模式频率、方法共现、A/B/C 题差异，更新 `知识库/写作增强/获奖论文模板与创新点.md`；写作前先读它定骨架与检验计划，再按题型检索单篇方法卡细化
- 赛题附件旧式 WMF/VML 图不当"空白图片"或交给整篇 OCR。先用 `tools/docx/scripts/extract_docx_content.py` 提取原生对象清单，再用 `--render-dir` 生成整页 PNG，视觉检查读取地图、节点、道路、图中规则；`Equation.DSMT4` 等 OLE 对象按公式对象单独核验
- 选模必须读匹配案例方法卡；五维门禁未过或解析质量低的案例只作待复核线索。质量合格算法可作候选模型依据；使用时写明本题适配理由、改造点、按题目需要的基线或验证计划
- 案例 `创新信号` 只能生成"本题创新候选"：补写本题差异、基线或验证计划；验证通过才写入论文创新点，不得当事实或照搬
- `知识库/方法库/` 已含：方法选择树、论文写法、图表规范、问题分类、QA 检查单——直接调用
- 解题按**题型匹配**同类案例，借算法思路和经验，重新定义变量、约束、参数、实现，不复用成品内容

### 10.4 生成新论文时

- **调用"经验"**：用学到的分析框架、表达节奏、图表范式组织**自己的**原创内容
- **不调用"原文"**：绝不打开库论文照抄
- 引用真实文献须经 `tools/paper_search/` 实际检索；仅 `citation_ready=true` 且书目已核验的条目入参考文献

### 10.5 全库归纳的建模与创新经验

- **模型递进而非单点炫技**：多个合理候选或需证明改进效果时，先用可解释机理模型、规则策略或统计基线给可行答案，再引入优化、仿真或学习模型处理关键复杂性；最终模型须解释相对基线多解决什么现实约束。单一自然模型不强行制造基线
- **把现实条件写进变量与约束**：优秀论文把容量、时间、风险、能耗、边界条件、数据缺失、决策规则显式数学化，不在结论口头补充
- **创新必须落到本题结果**：可迁移创新通常是目标函数更贴任务、约束更完整、策略可反馈、评价更全面或跨场景更稳定；按需用对照、灵敏度、误差分析、极限情形检查，不强制每项齐全
- **结果按决策链组织**：先给中间量或关键表，随后方案比较，再解释结果为何合理、何时失效；只报最终最优值不构成有说服力的结果分析
- **图表各司其职**：结构图解释对象变量，流程图解释求解步骤，曲线图解释动态过程，比较表解释方案优劣，敏感性图解释稳健范围；同一图不承担多种模糊任务
- **跨画像共同骨架**：热传导等机理题、动态资源决策题、信贷风险等数据题都保留"问题抽象—假设与变量—模型/算法—真实结果—适用性检查—可执行结论"主线；公式数量和检查方式按子问题调整
