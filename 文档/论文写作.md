# 论文生成规范（DOCX 单版本）

> **用途**：论文生成全链规范（审题→建模→求解→写作→格式合规）。
> **依赖**：`文档/样式统一规定.md`、`文档/代码规范.md`
> **被引**：多处（见 SKILL.md 加载表）

## 文档生成

论文 DOCX 由 `pf.new_document()` 编程创建，样式与页面由 `_ensure_paper_styles` + `setup_page` 统一注入，无需外部模板文件。

- 生成链路：`pf.new_document(contest="cumcm")` 创建空白文档并注入全部样式与页面设置。论文标题和章节按赛题增删改。
- 交付链路：`pf.save_document(..., filename="完整论文.docx")` 输出正式稿。
- 正文换行：`pf.body()` 把源文本换行合并为空格或中文连续文本；正文禁止强制换行。附录只留支撑材料清单（三线表，含哈希）。绕过入口写入的强制换行被结构校验拒交付。

论文手把 `results/` 真实运行结果（清单 `results/run_manifest.json`）写入 DOCX，生成经校验的交付物；提交 PDF 只从最终 DOCX 导出。生成与校验不依赖 Word/LibreOffice，不回退空白文档。无实际渲染页数时按内容等效页数下限核验。公式全部 Word 原生 OMML，图表全部真实运行结果。`save_document` 从同一内容快照**先落位 `完整论文.tex`、再发布 DOCX**（自动导出）（LaTeX 源码版，映射规则见 `文档/样式统一规定.md` §十二；不编译、不留 `.aux`/`.log` 构建文件）。

## 〇、论文铁律（不可违反；铁律 5/8 编号与 SKILL.md 对齐）

1. **原创底线**：可吸收优秀论文方法经验，但须结合本题数据、目标、约束重新设计、独立实现、真实运行验证；不得复制原文、公式写法、代码、数字、创新表述。可联网查背景、数据、文献辅助理解查证，**绝不抄袭**网络论文/题解内容。
2. **数值可复现**：每个结论有可运行代码支撑；关键结果用"两种独立方法"交叉验证。
3. **审题先于动手**：先用 `fitz`(PyMuPDF) 提取赛题 PDF 全文（中文 PDF 别用 PyPDF2），逐条列已知条件、给定表格、参数、各问所问。
4. **图必须自己插进论文**：`results/图片/` 每张登记图都用 `pf.add_figure(doc, path, "图N …")` 插到对应小节，否则 `save_document` 拒存。禁止图只留目录。
5. **直接朝终稿字数写**：从第一段起就按 §1.2 各节预算写满——每节下方的**内容模板**列出了该节须覆盖的内容要点（来源：`文档/七轮自审框架.md`、`文档/去AI味指南.md` 与优秀论文库归纳，见「优秀论文学习与经验迁移」节），逐条展开即可自然达到预算。写到预算区间内再进入下一节，这样全文自然达到 11111 字。**每章正文先在章源文件（`.paper_work/NN_*.md`）里把整章写成一块完整文本**——数清整章 CJK 字数，达到该章预算下限后整章一次性写入 docx（同一章只写一次，不得分批或后补段落）；某章低于预算说明分析深度不够，回到章源文本整体补机理推导、参数讨论或结果分析后全量重建 doc，不就地凑段。每写完一个中文序号一级章节、新开下一章前必须调用 `pf.emit_chapter_gate(doc)`：任一已写章低于预算下限即抛错拦截，**不写满不许进下一章**——本句由代码硬执行（结构校验 H 闸 `section_budget_errors`），不是口头要求。
6. **写不满就扩、不达标不交**：论文只以 `pf.save_document(...)` 交付。该函数强制纯黑并跑 `validate_paper_structure`；任一致命错误（页数/总字数/**章节字数下限**/图/表/公式不足、非黑字体、禁用词）**拒绝保存**。写作中途由 `pf.emit_chapter_gate(doc)` 提前拦同一缺额，避免跑到底才被拒。gate 报某章缺额时改该章源文本整块内容后重跑 build 脚本（每次运行都从 `pf.new_document()` 全新重建 doc），不维护第二份段落。

# 一、论文总架构

## 1.1 完整结构模板（按论文顺序）

```text
摘要（单独第 1 页，摘要与关键词合计不超过一页）
一、问题重述        ← 1.1 问题背景 / 1.2 问题提出（逐问列出各小问要求）
二、问题分析        ← 2.1 问题一分析 / 2.2 问题二分析 …每问一小节；
                       必要时在节末放一张"总体研究思路/技术路线"流程图（图1）
三、模型假设        ← 用"假设 N（短标题）：具体内容。"逐条编号，每条 1-2 句，禁止长段解释
四、符号说明        ← 三线表（符号说明）： 符号(正体) | 含义 | 单位；表前最多一句引入，表后不写说明段
五、模型建立与求解  ← 可按问题、模型模块、算法链或工况分 5.1 / 5.2 / 5.3 …
                       三级标题必须随内容命名，如"系统状态空间与事件驱动模型""综合优先级评分""随机故障滚动重调度"
                       不把 5.x.1/5.x.2/5.x.3 写死为"模型建立/模型求解/结果分析"
                       每个分支都要写清模型或算法、求解证据、结果解释与合理性分析
六、模型检验与分析   ← 6.1 数值验证与交叉检验，6.2 灵敏度分析（关键参数±变动看趋势）
                       6.3 误差/稳健性分析
七、模型评价与改进   ← 整节只保留 7.1 优点 5-7 条 / 7.2 局限与改进 4-6 条两个编号列表（与三/四节同纪律，每条 1-2 句），不再写介绍段/总结段
AI 工具使用声明    ← 参考文献**之前**，按《文档/论文评审.md》附录 B 固定文案
参考文献            ← 按 [1][2]… 编号，正文用"式/文献[1]"标注
附录                ← 附录A 支撑材料（源码/数据文件清单，由 run_manifest 自动生成；代码不入论文，本体保留在 code/）
```

- 标题编号体系与**命名具体化**规则（全文统一）：见 `文档/样式统一规定.md §三` 标题命名规则（反例/正例在该处）。
- 动笔前按 **「题型画像判定」**（附录内容节）判每个子问题的数学画像（几何/机理、优化/决策、数据/预测、评价/分类、图论/网络、仿真/不确定性），据此调建模重心、论文结构、图表职责；不按 A/B/C 题号硬套模型。

## 2.6 五、模型建立与求解

**篇幅**：正文主体章节，按 §1.2 预算表字数规划。

**组织方式**：
- 5.x 可按子问题、通用模型、算法模块、工况或验证回填组织
- 三级标题必须内容化命名（如"系统状态空间与事件驱动模型""综合优先级评分""随机故障滚动重调度"）
- 不把 5.x.1/5.x.2/5.x.3 写死为"模型建立/模型求解/结果分析"
- 每个分支都要写清模型或算法、求解证据和结果解释
- 不得另起与第五章并列的一级"结果分析"章节

**内容要求**：
- 正文每节**有内容**：分析深入、推导充分、参数解释清楚
- 每个 5.x 分支在第五章内完成结果解释与合理性分析，小标题按内容自拟
- 标题含"建立/建模"的小节必须 ≥1 个 oMath 公式——建模无数理表达式不成立

**图表分布**：
- 模型建立与求解章整章 ≥1 幅结果图（图N 题注）
- 图表按论证需用；后续引用已有图号，不重复插图；纯解析小问不硬塞
- 图表按正文出现顺序分散到对应小节；禁章末堆图、禁连续≥3视觉对象无解释段

**内容模板**：
- 每节开头说明"解决什么"。
- 说明模型为何适配；有合理候选交代取舍，无则不强造比较。
- 公式从问题推导（非抄教科书标准形式），每参数含义与取值依据说明。
- 有算法伪代码或流程图。
- 求解参数/停止条件/收敛/可行性证据来自真实运行记录。
- 每图表后自然地介绍图表内容并给出简单解释，不能只写"由图可知"。
- 每子问题有相称的误差/可行性/极限/基线/灵敏度检查。
- 各 5.x 分支完成"模型/算法—求解证据—结果解释"闭环。

## 2.7 六、模型检验与分析

**篇幅**：按 §1.2 预算表字数与题目需要规划。

**检验类型选择**：
从数值一致性、可行性、误差、极限情形、基线、灵敏度或稳健性中选择与本题相称的检查，不强制同时使用所有项目。

**按题型选择**：
| 题型 | 必选检查 |
|---|---|
| 几何/机理 | 量纲、边界条件、极限情形、解析解或实测对比 |
| 优化/决策 | 约束满足、方案可实施性、简单基线、目标变化 |
| 数据/预测 | 留出集/交叉验证、误差指标、残差、失败样本 |
| 评价/分类 | 指标方向、权重变化、类别平衡、排名/聚类稳定性 |
| 图论/网络 | 节点边完整性、路径可达性、边权解释、容量约束 |
| 仿真/不确定性 | 随机种子、试验次数、分布摘要、区间、场景边界 |

**格式要求**：
- 模型检验与分析章 ≥1 幅检验图（灵敏度/误差/稳健性曲线）+ ≥1 张检验结果表（表N 题注）
- 检验章不允许纯文字，写前在 figures_plan 给检验章预登记图槽
- 分点说明检验对象与结论，不展开冗长论述

**内容模板**（检验设计与表述对照 `文档/七轮自审框架.md` 附录 F 反模式反向规避）：
- 模型检验是区分获奖档位的关键章节，须用数据支撑结论可信度。
- 按上方题型表选取适用检验类型，关键参数确实影响结论时再做灵敏度分析，且扰动幅度贴合实际、扰动范围与适用边界须说明（勿蹈附录 F 中"仅 OAT、扰动失实、不报稳健区间"等反模式）。
- 每项检验写清：检验对象 → 做法 → 关键数值/图表 → 结论。
- 稳健性声称不得超出已完成的检查范围，脆弱结论须标记。

## 2.8 七、模型评价与改进

**篇幅**：服从正文总字数下限。

**格式要求**：
- 7.1 优点 5-7 条、7.2 局限与改进 4-6 条，每条 1-2 句指向具体设计/边界
- 整节唯一正文形态 = 7.1/7.2 两个紧凑编号列表（与模型假设、符号说明同纪律），不在子标题上下文写介绍段/总结段等任何非编号正文

**示例**：
```
7.1 优点
（1）统一内核：五问共用一套模型，交叉验证天然成立。
（2）硬约束优先：速度传播具有非平凡几何变化，可刻画紧弧区域速度放大。

7.2 局限与改进方向
（1）碰撞模型为平面矩形，未考虑厚度；对参数敏感性已量化，量级为毫米—厘米。
（2）问题五仅在匀速口径下给出答案，变速策略的时间最优问题未展开。
```

**内容模板**（按 `七轮自审框架.md` 附录 H + `去AI味指南.md` §四）：
- **7.1 优点**（5-7 条，每条 1-2 句）：指向本题事实——变量少、约束完整、两种方法可互验、运行时间可控、边界行为正确等，有量化证据支撑，不夸大（H2）。
- **7.2 局限与改进**（4-6 条，每条 1-2 句）：局限落到具体假设/数据/计算边界（H1），不写"数据有限/场景复杂/未来进一步研究"等万能句；改进落到具体动作——换优化算法、加阻尼项、推广 n 人 m 鼓等（H3），不写"将进一步研究"。**改进条数不够时从被忽略的约束/极端参数区/耗时瓶颈逐条再挖 2 条**。
- **创新点**：一句话并入 7.2 作为一条编号条目（概括本题化改进点及实际影响，不套用案例表述），不单独成段。
- 与模型假设、符号说明同纪律：整节只放两个紧凑编号列表，不写三级标题，不在子标题上下文再写介绍/总结等大段话。

## 2.10 参考文献

**篇幅**：不设字数，只限数量；数量闸门见文末"项目交付下限表"。

**内容要求**：
- 按 [1][2]… 编号，正文用"式/文献[1]"标注
- 正文引用处标注 [1][2]…，与文末一一对应
- 真实且正文对应；每条 [n] 须在 `results/数据/文献检索.json` 命中书目来源（`_reference_registry_issues` 硬校验，缺文件或无命中即拒存）
- 真实来源优先 `tools/paper_search/` 输出中 `citation_ready=true` 的结果；`citation_ready` 只证书目信息，不证观点支持本题结论

**著录格式**：按 GB/T 7714：期刊 `[J]`、会议 `[C]`、图书/专著 `[M]`、学位论文 `[D]`、报告 `[R]`、标准 `[S]`、专利 `[P]`、数据集 `[DS/OL]`、电子文献 `[EB/OL]`。

**年份门禁**：只收 2016 年及之后（`contest_profile.REFERENCE_MIN_YEAR`，`_reference_issues` 硬校验，早于下限拒存）。

**文献取向**：以近 10 年文献为主（方法与数据类尽量新，经典文献可更早）；参考文献表以中文文献为主（中文宜多于英文）。

## 2.11 附录

**篇幅**：按源码实际长度，不设项目自定义行数上限。

**内容要求**：
- 只有**附录A 支撑材料**：由 `run_manifest.json` 的 `source_scripts` + 数据文件自动生成清单（`pf.append_code_files(project_root)` 渲染）
- 非空赛题必有实质内容
- 各小问核心代码**不进论文**，全部以 `code/Q<序号>_*.py` 文件交付，清单登记其路径与哈希

# 四、交付前自检

## 4.1 结构校验

生成后必须用 `tools/docx/` 的 `validate_paper_structure()` 校验，并重开最终 DOCX 抽检结构、公式、表格、图片、页脚、字体。交付前统一跑 `python tools/docx/scripts/self_check.py --docx 完整论文.docx`（工具链自检 + 模板化表达扫描）。项目不自动生成 PDF。

独立复核 DOCX：`python tools/docx/scripts/validate_paper_json.py <docx> --project-root <project>`。调试结构：`python tools/docx/scripts/export_paper_structure.py <docx> --output structure.json`，输出标题层级、图、表、公式及文档顺序。

## 4.2 内容校验

**前置校验清单（写作时逐条遵守，不等 gate 后修）**：

1. **小节最低篇幅**：每个二级小节 ≥ 300 字。禁止空标题/占位标题（标题含 XXX/TODO/待填 或标题下无正文段落——机器闸门拦截）。
2. **公式→参数→数值链**：正文引用公式中每个符号必须有定义（符号说明表或上下文），参数值必须对应 `run_manifest.json` 登记来源。
3. **结论有据**：模型结论断言（"最优"/"显著"/"收敛"）必须有 manifest 数据支撑，无登记依据的表述禁止写入。
4. **统计结论守卫**：声称"显著"须附 p 值与效应量，声称"最优"须附对比基线数值，声称"收敛"须附迭代/残差数据。
5. **图表前置引导**：每张图/表在正文首次出现前必须有引导句（如"如图 3 所示，…"），禁止无前文铺垫直接出现。图编号严格按正文出现顺序递增，不得乱跳。
6. **一次提交即达标**：首次提交 gate 校验时正文须已达 11111 字以上（按 §1.2 各节预算逐节写满即可自然达到）。禁止"先写短稿再扩写"——逐章 `emit_chapter_gate` 硬断点会拦下缺额章（低于预算下限即抛错），补深度内容须回到章源文本整体改写后重建，整章一次性写入 docx，不要在已有段落后加段落。

**证据纪律（从产物出发，核心原则不变）**：

写作只认产物，不认感觉。正文、摘要、附录、结论里每句判断都要能在结果文件、图表、公式推导、脚本输出或稳健性检查里找到依据。

**能写**：问题解析、最终方法说明、人工决策台账、数据画像、脚本、冻结数值、图表、稳健性报告、方案包、质检笔记；每章写"做了什么/为什么这样做/结果说明什么/边界在哪"；摘要写问题/方法/主要结果/检验边界；问题重述只写题目已给出的背景/目标/子问题/产出/约束。

**不能写**：无证据的数据/数值/参考文献/图表/参数/实验结论/模型性能声称；无基线不写"更优"；无稳健性不写"全局稳健/鲁棒性强"；无结果支撑不写空泛结论。

**句子检查六问**：回应哪子问题？由哪产物支撑？是否数值声称？数值在结果文件里？需基线/稳健性？措辞是否超证据？

**交付原则**：有证据弱声称 > 无证据强声称；技术语气克制、句子短、主语具体、结论留边界。

**论证纪律**：

写作时逐条遵守，不等定稿后自查。

**主张必须有来源**：每句结论对应题目条件、公式推导、运行输出或文献原文之一。comparison / mechanism / sensitivity / boundary / innovation 类主张须有对应证据（同数据同指标对照、独立推导、扰动实验、边界检查、本题化验证）。

**论证避坑**：
- 悬空主张（无来源）→ 删 / 改弱 / 补算
- 跳跃逻辑（A→C 缺 B）→ 补中间步骤
- 循环论证（用结论证结论）→ 引入独立证据
- 一图撑多结论 → 拆分解释或收窄结论
- 稻草人基准 → 选公认强方法重对比

**反方测试**：对每核心结论问"哪些条件下不成立"，无法回答则补边界或弱化结论。

**证据分层**：`citation_ready=true` 只证书目信息层（作者/年份/DOI 可查），不证观点证据层。正文引用具体方法 / 结论 / 因果时须另核原文定位；找不到 → 删观点 / 改弱 / 换来源。

**图表·公式·符号一致**：编号全局连续、正文引用与图表对应、符号首次出现前已定义、符号表与正文完全一致。

**子问题复用链**：下游使用上游结果时标注来源、版本、单位与误差传播，不凭空 reuse。

**证据链闭环**：参考文献编号对应文末文献、附录仅放复现所需代码、AI 声明指向支撑材料。

## 4.3 格式校验

**当届竞赛格式要求**：

1. **纸质版顺序**：第 1 页承诺书，第 2 页编号专用页，第 3 页摘要专用页，第 4 页起正文；摘要与关键词合计不超一页。电子版不含承诺书和编号页，页码从第 1 页到末页连续。

## 优秀论文写法（按题目适配）

除格式合规外，优先写清真正解决本题难点的建模选择。同组变量、同求解对象、两法互验、灵敏度分析、全情景计算都是按需工具；完整源码与真实结果始终保留。

### 题型画像判定

> **动笔前先按本节判定每个子问题的数学画像**，据此调建模重心、论文结构、图表职责；不按 A/B/C 题号硬套模型。一道题可含多个画像；先逐问判断，再定模型、公式、图表、检查方式。

**产出画像速查**：

| 画像 | 主要产出 | 写作重心 | 优先图表 |
|---|---|---|---|
| **几何/机理** | 方程、轨迹、场、参数、物理解释 | 假设、变量、边界、逐步推导、量纲、极限情形 | 几何图、演化曲线、模型-解析/实测对比 |
| **优化/决策** | 可行方案、排程、路径、资源分配 | 决策变量、目标、约束、求解步骤、可行性 | 技术路线、方案对比表、路线图、收敛/排程图 |
| **数据/预测** | 预测值、趋势、误差/区间 | 数据质量、特征/变量、训练检验划分、误差解释 | 数据概览、趋势图、预测对比、残差图 |
| **评价/分类** | 得分、排名、类别、异常 | 指标方向、权重/分类规则、分组解释、稳定性 | 指标表、排名图、分布图、混淆矩阵/聚类图 |
| **图论/网络** | 路径、流量、匹配、连通、覆盖 | 节点边抽象、边权、路径约束、可行性 | 网络图、路线图、覆盖图、流量/匹配表 |
| **仿真/不确定性** | 场景结果、分布、风险/区间 | 随机设定、场景构造、试验次数、统计摘要、边界 | 场景对比、分布图、置信区间、风险曲线 |

### 建模组织：让各问有关系但不强行统一

- 小问间确有输入输出关系 → 一条主线贯穿；各问对象不同 → 分别建模，问题分析写清边界，不为统一结构强行拼接。
- 先画问题分解与结果依赖：每个 5.x 分支能回答"解决哪个子问题、用哪个输入、输出什么、为后续哪步供什么"；无真实依赖不强行串联。
- 高级方法用在"刀刃"上并说明为何合适：姿态用**四元数**（避万向锁）；运动方程用**四阶 Runge-Kutta** 积分；误差校正用一阶傅里叶分解 `T_i = T0+ΔTz+a·cosφ_i+b·sinφ_i` 解耦"整体升降 ↔ 两向倾斜"；拉力分配用余弦规律 `T_i = T0 + A·cos(φ_i−ψ_c)` 或力矩逆解。
- 简化必须有依据：**小角度假设要先被"完整模型"验证过**才敢用。

### 求解检查：选择与问题相称的核验方式

- 关键数值存在可比方法时用两套独立方法交叉检查；几何/机理题用极限情形或量纲检查，优化题用可行性和基线检查，数据题用留出集、交叉验证或残差检查。
- 模型/算法选择写清本题适配理由、合理替代方案及取舍；无合理替代时说明"为何不需强行比较"，不为形式制造第二模型。
- 求解过程记录实际关键参数、停止条件、收敛/可行性证据、失败处理；无运行记录的过程不得补写。
- 主动纠正常见公式符号错误（如碰撞反弹公式用 `(eM−m)`，避免 `(m−eM)`），并说明修正理由。
- 对确实影响结论的参数做灵敏度或扰动分析；参数不敏感、无扰动含义或计算规模不允许时说明原因，改用更合适检查。
- 引入真实约束体现工程思维：量化"人体反应时延约 0.2 s"对纠偏残余误差的影响，给出"分 2–3 次渐进纠偏收敛"的可操作结论。

### 表达创新：让评委一眼看懂巧思

- 多问递进时，问题分析开篇或节末放总体研究思路/技术路线流程图，节点写本题变量、动作、输出；独立小问不强行画空流程图。
- 第五章标题内容驱动：按"通用模型、算法模块、工况分支、子问题"组织；机械套用 `模型建立 → 模型求解 → 结果分析` 会僵化。图片放首次解释其信息处，后续引用已有图号，不重复插入。
- 图分层服务论证：几何示意图、结果曲线、反馈/纠偏流程图、倾斜轴方位图各司其职。
- 题目存在反馈、迭代、动态纠偏时，把误差作为状态变量并报告校正前后变化；无此类结构时改写为普通误差分析或稳健性说明。
- 模型评价写具体：优点指向变量少、约束完整、两法互验、运行时间可控等事实；缺点写清依赖理想参数、忽略绳弹性等边界；改进落到换优化算法、加阻尼项、推广 n 人 m 鼓等具体动作。

### 严谨性创新：主动堵上可被挑刺处

- 合理性检验：结果与物理直觉/极限情形比对（等幅稳态、最小能耗临界等）。
- 误差与不确定性：给数值量级估计，说明可信区间。
- 文献与数据：引用通用教材/手册并正文标注；不杜撰数据。

### 完整性创新：超出题目要求的加分项

- 题目给的所有情景都算全（如 9 种发力情形全列倾角，只算 1 个不符合全情景要求）。
- 附录只放附录A 支撑材料清单；源码在 code/ 目录，与本次运行结果严格一致。
- 讨论推广价值：模型可迁移到哪些同类问题（多体协同、柔性绳、不同几何体）。

## 高区分度写法（加分项速查）

1. 问题分析存在多问递进、数据流或决策链时，放"总体研究思路"流程图（图1），一眼看懂各问关系。
2. 每个 5.x 分支按输出形式选中间结果表、结果图或推导段，不只抛数字；变量关系和结论含义写在该分支内容化小节中，可叫"结果分析"、"稳健性验证"、"方案对比"、"滚动重调度效果"等。
3. 每张图表后自然介绍内容并给简单解释；不能只写"由图可知"。
4. 关键参数确实影响结论时再做灵敏度分析；图表和正文说明扰动范围及适用边界。
5. 模型评价写清"优点/缺点/改进推广"，不空泛；每条优点、缺点、改进绑定本题数据、假设、参数或验证结果。
6. 参考文献按 GB/T 7714 著录：期刊 `[J]`、会议 `[C]`、图书/专著 `[M]`、学位论文 `[D]`、报告 `[R]`、标准 `[S]`、专利 `[P]`、数据集 `[DS/OL]`、电子文献 `[EB/OL]`；正文引用按编号标注。**年份门禁：只收 2016 年及之后**（`contest_profile.REFERENCE_MIN_YEAR`，`_reference_issues` 硬校验，早于下限拒存）。真实条目优先 `tools/paper_search/` 输出中 `citation_ready=true` 的结果（检索可按年份下限过滤）；`citation_ready` 只证书目信息，不证观点支持本题结论。
7. 项目保留完整可运行源码（code/ 目录）；论文附录只放附录A 支撑材料清单，代码不入论文。

## 优秀论文学习与经验迁移

> 来源：`知识库/优秀论文案例/`（优秀论文库）与 `知识库/方法库/`（方法库）。**允许迁移算法思想和建模经验，但必须结合本题重构、独立实现、重新验证；绝不抄内容。**

### 学什么（六类可迁移经验）

1. **问题分析方式**：如何把模糊赛题拆成可建模子问题
2. **模型递进方式**：从简单基线到复杂模型的演进逻辑
3. **数学表达方式**：公式组织、符号约定、推导节奏
4. **结果解释方式**：把数字讲成"有说服力的结论"
5. **图表设计方式**：选图、标注、配色最清晰
6. **论文排版规范**：结构、篇幅、匿名、附录处理

### 禁止什么（红线）

- 复制文字、公式、代码、具体数字、原论文创新表述——任何形式都不行；算法思想可本题化迁移
- 直接复用某篇优秀论文"整体框架"当自己论文
- 把库中文献当真实引用塞进新论文（未真正读过不得引用）

### 如何形成经验库

- 用户上传优秀论文 PDF → `tools/paperingest/` 自动抽取文本层或 OCR 扫描页 → 逐篇生成同名五维方法卡（原文证据位置、排版逻辑、模型假设、方法命中、创新信号、图表组织）。新赛题用 `python tools/project_ops/case_retrieval.py --query-file <赛题 PDF> --query-file <赛题 DOCX> --top-k 5` 合并两个版本，PDF/DOCX 不启用 OCR；DOCX 中 WMF/EMF、VML、OLE 对象另由附件提取器清单化，对全部 Markdown 卡片按题型、方法、约束排序，不维护单独索引
- 全库蒸馏：`python tools/paperingest/distill.py --raw <PDF目录>` 跨论文统计章节骨架出现率与顺序、创新点模式频率、方法共现、A/B/C 题差异，结果打印到 stdout；统计供会话内定骨架与检验计划参考，写作前按题型检索单篇方法卡细化
- 赛题附件旧式 WMF/VML 图不当"空白图片"或交给整篇 OCR。先用 `tools/docx/scripts/extract_docx_content.py` 提取原生对象清单，再用 `--render-dir` 生成整页 PNG，视觉检查读取地图、节点、道路、图中规则；`Equation.DSMT4` 等 OLE 对象按公式对象单独核验
- 选模必须读匹配案例方法卡；五维门禁未过或解析质量低的案例只作待复核线索。质量合格算法可作候选模型依据；使用时写明本题适配理由、改造点、按题目需要的基线或验证计划
- 案例 `创新信号` 只能生成"本题创新候选"：补写本题差异、基线或验证计划；验证通过才写入论文创新点，不得当事实或照搬
- `知识库/方法库/` 已含：方法选择树、论文写法、图表规范、问题分类、QA 检查单——直接调用
- 解题按**题型匹配**同类案例，借算法思路和经验，重新定义变量、约束、参数、实现，不复用成品内容

### 生成新论文时

- **调用"经验"**：用学到的分析框架、表达节奏、图表范式组织**自己的**原创内容
- **不调用"原文"**：绝不打开库论文照抄
- 引用真实文献须经 `tools/paper_search/` 实际检索；仅 `citation_ready=true` 且书目已核验的条目入参考文献

### 全库归纳的建模与创新经验

- **模型递进而非单点炫技**：多个合理候选或需证明改进效果时，先用可解释机理模型、规则策略或统计基线给可行答案，再引入优化、仿真或学习模型处理关键复杂性；最终模型须解释相对基线多解决什么现实约束。单一自然模型不强行制造基线
- **把现实条件写进变量与约束**：优秀论文把容量、时间、风险、能耗、边界条件、数据缺失、决策规则显式数学化，不在结论口头补充
- **创新必须落到本题结果**：可迁移创新通常是目标函数更贴任务、约束更完整、策略可反馈、评价更全面或跨场景更稳定；按需用对照、灵敏度、误差分析、极限情形检查，不强制每项齐全
- **结果按决策链组织**：先给中间量或关键表，随后方案比较，再解释结果为何合理、何时失效；只报最终最优值不构成有说服力的结果分析
- **图表各司其职**：结构图解释对象变量，流程图解释求解步骤，曲线图解释动态过程，比较表解释方案优劣，敏感性图解释稳健范围；同一图不承担多种模糊任务
- **跨画像共同骨架**：热传导等机理题、动态资源决策题、信贷风险等数据题都保留"问题抽象—假设与变量—模型/算法—真实结果—适用性检查—可执行结论"主线；公式数量和检查方式按子问题调整

## 赛题详解与结果分析规范

> 分析内容（题目理解、问题拆解、思路、模型设计论证、结果解释、创新点）**直接组织进论文正文对应章节**（问题重述 / 问题分析 / 模型建立 / 结果分析 / 结论），并沉淀进 `results/论文评审与分析.md` 的修改闭环；**不单独产出 `results/赛题详解与结果分析.md` 或任何独立分析报告、结果分析、阶段小结文件**。结果清单以 `results/run_manifest.json` 为唯一登记。

### 选模前置：案例检索

选模前必须跑案例检索工具，按宽题目画像、方法和约束匹配"案例五维方法卡"。画像只扩大参考范围，不按 A/B/C 题号分流：

```bash
python tools/project_ops/case_retrieval.py --query-file <赛题 PDF> --query-file <赛题 DOCX> --top-k 5
```

工具输出参考块**仅进会话上下文**供本题化设计，不落盘任何检索报告。不得只凭案例标题或原始 PDF 直接套用模型。

### 案例参考转化规则

会话上下文保留每个入选案例四项信息（案例卡路径、题目画像与匹配依据、可迁移方法、本题化候选），按需写入论文正文模型设计小节。候选方案须经以下转化才能进模型方案：

1. **案例经验**：案例解决了什么结构问题，用什么模型族、约束表达、验证方式。
2. **本题差异**：本赛题的数据、目标、约束、规模、不确定性与案例有何不同。
3. **本题候选创新**：只提出可由本题数据验证的改进，如现实约束量化、目标函数扩展、动态/鲁棒情景、基线对比、验证闭环。
4. **核验计划**：明确用什么数值检查、基线、对照实验、灵敏度分析、极限情形或鲁棒性检查确认候选方案适用。非每类题都须同时使用。

> 案例卡 `创新信号` 是候选方向，非原论文真实创新结论；低质量案例只作待复核线索。案例卡不得进论文参考文献，真实引用必须来自 `tools/paper_search/` 的 `citation_ready=true` 结果；论文具体观点仍须原文证据，不得凭标题或摘要推断。

### 写作总则

- 像高水平建模队员做的**内部技术笔记 + 方案论证**，逻辑严密、推导充分、可读。
- 每条结论能回到实际数据、推导、实验或题目条件，禁空话与"显然"；不要求逐句证据台账。"优于、显著、鲁棒、因果、创新"等强结论必须补可比实验、推导、边界检查或真实文献依据；证据不足收窄措辞。
- 模型选择讲清"为什么适配本题、有哪些合理候选、最终为何取舍"，禁直接堆公式；无合理候选不强行制造比较。

### 七节强制结构

#### 1. 题目理解
- **研究背景**：题目来自什么现实场景，解决什么科学与工程问题。
- **核心问题**：一句话点破数学本质（优化 / 预测 / 评价 / 分类 / 仿真…）。
- **数学本质**：文字题翻译成数学对象（变量、约束、目标、已知/未知）。

#### 2. 问题拆解
逐问分析（几个子问题列几个）：
- **问题目标**：这一问产出什么。
- **输入数据**：用什么数据 / 需要哪些量。
- **输出目标**：交付什么结果（数值、曲线、方案、排序…）。
- **难点分析**：卡点在哪（数据缺失、非线性、多目标、不确定…）。

#### 3. 整体解题思路
给完整路线（箭头串联）：

```text
数据处理 → 模型建立 → 算法求解 → 结果分析 → 模型优化
```

每一环写清"做什么、为什么这样排"。标明各环节输入、输出、证据来源，避免"数据—模型—结果"空流程。

#### 4. 模型设计

> 选型遵循本档「题型画像判定」：先判子问题产出和数学结构，再从相容方法族选主模型。确有可比候选才做基线或多方案比较；不强制跨模型族挑战者。

对每个候选/最终模型：
- **为什么选它**：适配题目哪点。
- **模型思想**：直觉与机理。
- **数学表达**：核心公式用可直接转 LaTeX 的单行写法记录，按"定义/依据 → 推导 → 结论或用途"展开；变量先定义后使用。
- **变量定义**：表格化符号说明。
- **假设条件**：必要假设 vs 简化假设，各写理由与影响。
- **求解方法**：算法名 + 步骤 + 关键超参；记录真实参数依据、停止条件、收敛或可行性检查，不补写未经运行的"调试过程"。

#### 5. 最优方案说明
- 明确**最终采用哪个方案**。
- 有合理候选时解释最终方案为何适配本题，同数据、同指标、同约束下说明选择依据；无合理替代不强行多模型对比。准确性、稳定性、可解释性、本题化改进只写有证据部分。

#### 6. 结果分析

> 所有数值结论来自 `results/` 真实运行产物；按题目需要做误差、可行性、极限情形、基线或参数检查，不要求所有题用同一证据模板。

**必须结合真实运行结果**（数值来自 `results/`，不得编造）：
- **图表解释**：每图说明展示对象、关键趋势或差异、可能原因、对本问的作用；不得只写"由图可知"。
- **参数分析**：关键参数敏感性、鲁棒性。
- **模型检查**：按题目类型选误差指标、交叉验证、对照实验、基线比较、极限情形或可行性检查。
- **证据边界**：明确结果适用数据、参数、场景范围；单次实验不成普遍规律，相关性不直接写因果。

#### 7. 创新点总结
- 只写**真实创新**：新方法、新组合、新视角、新数据处理。
- 禁把普通步骤包装成创新。每条创新点写清"新在哪、带来什么提升"，给对应结果或推导；无实证提升只写"本题化处理"或"方案特点"。
