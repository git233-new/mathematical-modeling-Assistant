# 图片闸门配置与绘图规范

> **用途**：图表规范机器闸门层（H1–H12 / W1–W12 / D1–D4），validator 直连。
> **依赖**：无
> **被引**：`文档/论文写作.md`、`知识库/方法库/图表规范.md`

本文档固化 validator 与绘图层的闸门配置。目标：把"靠人盯"的写作/绘图软规则，转为机器可查的硬闸门 + warning 级软闸门 + 纯文档软建议三层体系，使实战自动合规，不依赖人工挑刺。

---

## 0. 出图字体与渲染基线（强制，仅约束 skill 内部模板/脚本出图）

> 本节是 **skill 内部出图**（`tools/figure/templates/` 与 `audit_figures.py` 等）的基线，由 validator 校验其必须调用 mm_style 样式函数。
> **赛题交付代码不使用本节**：它零 skill 依赖、完全自包含，在 Q 文件内就地把 `font.sans-serif` 设为 `["SimHei", "Microsoft YaHei", "SimSun"]` 并配 `axes.unicode_minus=False`、`figure.dpi=300`（见 `文档/代码规范.md`）。两套均 SimHei 打头，见一致性下文。

- 所有 skill 内部绘图**统一经由 `tools/figure/runtime/mm_style.py` 的默认 `plt.rcParams`**：
  - `font.sans-serif = ["SimHei", "Microsoft YaHei", "SimSun", "NSimSun", "DejaVu Sans"]`（中文黑体 SimHei 打头，与 `mm_style.CHINESE_FONT` 及代码规范自包含片段一致，回退微软雅黑/宋体）
  - `font.size = 11`
  - `DPI = 300`
- skill 内部绘图脚本**必须调用 `mm_style.configure_chinese_style()` / `configure_matplotlib()` 或 `apply_publication_style()`**，并复用其 rcParams 默认。
- **禁止**在脚本内另设 `font.sans-serif` 把 `Arial` 排在其首位之前，否则中文被 Arial 抢占变方块；`SimHei` 必须存于首部，黑体可用时优先（与正文 `paper_format.set_run_font('宋体')` 的正文区分，图内统一黑体基线）。
- PNG 内嵌字体 docx 层不可见，validator 无法反查像素字体；故中文字体靠**生成层默认兜底**，不进 validator 硬闸门（脚本字体只到 W5 软闸，见下）。

## 1. 配置约束：同一张图片不得被重复写入硬闸门

- 每张登记的图片（`results/图片/*.png`）在硬闸门体系中**只对应唯一一个质量闸门**。
- 图片质量统一由**单图质量闸门**一次判定（dpi≥300、中文字体正常（SimHei 打头）、文字无遮挡、题注存在且被正文引用），**不**分散为多个硬闸门对同一图重复检查/重复报错。
- 即：一张图只写一次硬闸门。禁止把"图 N"同时塞进"清晰度闸门""字体闸门""遮挡闸门"等多个独立硬闸门导致重复判定冲突。
- 非图片类硬闸门（摘要、模型假设等）不受此约束，但同样遵循"每项检查单一归属"原则，避免重复扫描同一文本段。

## 2. 硬闸门（12 条，error 级，不合规即 build 失败）

| ID | 检查项 | 机器判法 | 来源 |
|----|--------|----------|------|
| H1 | 摘要三段式结构 | 摘要区（`摘要`标题→`关键词`前）段落数 == 3 | 摘要写作范式.md §八 |
| H2 | 摘要区纯文本·中文 | 摘要区查含图（`a:blip`）→ error；字母占（中文+字母+数字）总量 >15% → error（禁英文翻译） | 摘要写作范式.md §二 |
| H3 | 摘要页≤1页 | 摘要+关键词合计字数 >1000 → error（目标 800–900 字，一页近似） | 摘要写作范式.md §二 |
| H4 | 摘要占首页 | 摘要区（`摘要`→`关键词`）内出现 Heading 1 样式段落 → error（摘要须紧接论文标题独占开篇） | 摘要写作范式.md §二 |
| H5 | 问题分析平衡（禁一头沉） | 导论段数 ≤ 2，且每个 2.x 小节段数 ≥ 2 | 问题重述与分析写作.md |
| H6 | 模型假设逐条编号 | 假设段匹配 `^假设\s*\d+`（可含 `（短标题）`，冒号 `：` 收尾）正则，且条数 ≥ 3 | 论文写作.md / 假设与符号写作.md |
| H7 | 符号说明题注后不写描述 | 符号说明题注段后、下一级 H1/H2 前，prose 段落数 == 0 | 论文写作.md |
| H8 | 符号说明表 ≥ 12 行 | 符号表 row 数 ≥ 12 | 论文写作.md |
| H9 | 附录表为三线表 | 附录内表格 `border`：top/bottom `single` 且 left/right 关闭；缺表线拒存（正文大型数据表仍允许闭合方框表） | 论文写作.md |
| H10 | 图/表题注冒号统一 | 所有题注匹配 `^(图|表)\d+：` 格式（中文冒号） | 论文写作.md |
| H11 | 元叙述空话红线 | 全文正则扫 `["整体技术路线","研究范式","综合评价方法","研究逻辑是","方法学价值","论文整体"]` 等，命中即报 | 自审框架.md(3.1) |
| H12 | 匿名 | 禁用词扩 `["大学","学院","赛区","学校","姓名"]` + 可配置校名表 | 论文写作.md |

> H9 与正文三线表闸门（`_three_line_table_issues`）协同：正文表查三线/方框两种合法形态（禁两线表与带竖线网格表），附录表只认三线形态（附录A 清单），缺表线即拒。

> **附录图表不纳入结构检验**：图/表数量、题注编号与正文引用、等效页数折算均只统计参考文献/附录之前的正文（口径统一见《文档/论文写作.md》）。

## 6. 图表分类管理（诊断图永不进正文）

> 对应 `文档/七轮自审框架.md` 第 5–7 轮。每张图在产出时按用途打类别标签，写入 `results/图片清单.md`；只有「论文用」图进入正文，诊断图绝不混入。

### 6.1 四类图表

| 类别 | 用途 | 是否进正文 | 硬性要求 |
|------|------|-----------|---------|
| **诊断型** | 调试中间态、数据清洗前后对比草稿、字体渲染诊断、异常值检查 | 否，永不进正文 | 仅用于开发期自查，不进 `results/图片/` 论文批次 |
| **对比型** | 展示方案/模型/参数对比，须含基线或参照对象 | 可选 | 必须含基线或参照对象，否则退化为诊断图 |
| **论文用** | 进入论文正文、支撑关键结论 | 是 | 通过视觉渲染验证（字号≥11pt、dpi≥300、中文标签、无遮挡） |
| **附录用** | 大篇幅中间结果、完整参数表、补充图表 | 仅附录 | 随附录打包，不占用正文图表闸门 |

### 6.2 管理流程

1. 出图时在脚本注释或 `results/图片清单.md` 中标注类别（`diagnostic` / `comparison` / `paper` / `appendix`）。
2. 诊断图仅留在开发目录，**不登记进 `run_manifest.json` 的 `figures`**；`result_contract.write_run_manifest` 只接受 `results/` 下论文批次图。
3. `structure_validation` 对 `run_manifest.figures` 内每张图做存在性/哈希/题注核对——诊断图不在登记批次，天然被排除在正文之外。
4. 对比型图进正文前，先确认其已含基线/参照对象（E4 反模式联动）。

### 6.3 与硬闸门的关系

图表分类是**写作纪律 + 登记纪律**，机器层面有两道闭环：

1. **登记图必须进正文**：`run_manifest.figures` 登记图须在论文中找到且哈希一致，否则 `_manifest_figure_issues` 报「登记图未插入/哈希不符」。
2. **`results/图片/` 图必须都用**：该目录下所有图都须嵌入论文，否则 `_result_figure_issues` 报「results/图片/ 中未插入正文的图片」。

因此**诊断图应只留在开发目录，不放入 `results/图片/`、不登记进 `run_manifest.figures`**；一旦误放入 `results/图片/` 或误登记，闸门会因「未插入正文」而拒绝交付。分类标签由作者在 `results/图片清单.md` 标注、评审时人工核对；该 md 为**作者临时记录文件，不列入交付契约**，`project_cleanup.py` 清理时对其豁免（不在保护名单内则视为可删中间文件，作者应按需保留）。诊断图混入正文时，由上述「登记但未插入」「未登记却在 results/图片/」两道对账拦截。
