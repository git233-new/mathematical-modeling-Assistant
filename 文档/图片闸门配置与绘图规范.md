# 图片闸门配置与绘图规范

> **用途**：图表（图/表对象）相关机器闸门与绘图层规范的唯一权威；只登记图表闸门。
> **依赖**：无
> **被引**：`tools/docx/core/structure_validation.py`、`文档/论文写作.md`、`知识库/方法库/图表规范.md`

> 本文档只写与图表有关的规定。论文文字/结构类闸门（摘要、问题分析、模型假设、符号说明、章节预算、查重、去 AI 味、匿名等）不在本文档登记——它们由 `structure_validation.py` 实现，规则登记在各自来源文档（摘要写作范式/问题重述与分析写作/论文写作/假设与符号写作等）。为避免编号漂移，凡涉及 H/W 编号处一律与 `structure_validation.py` 代码注释链对齐，本文档仅收录图表相关行。

## 0. 出图字体与渲染基线（强制，约束 skill 内部模板出图）

> **赛题交付代码不使用本节**：它零 skill 依赖、完全自包含，在 Q 文件内就地把 `font.sans-serif` 设为 `["SimHei", "Microsoft YaHei", "SimSun"]` 并配 `axes.unicode_minus=False`、`figure.dpi=300`（见 `文档/代码规范.md`）。两套均 SimHei 打头，见一致性下文。

- 所有 skill 内部绘图（`tools/figure/templates/*.py`、运行时 helper）**统一经由 `tools/figure/runtime/mm_style.py` 的 rcParams 单一来源**：

| rcParams 键 | 值 | 覆盖对象 |
|---|---|---|
| `font.sans-serif` | `["SimHei", "Microsoft YaHei", "SimSun", "NSimSun", "DejaVu Sans"]` | 中文黑体 SimHei 打头（与 `mm_style.CHINESE_FONT` 及代码规范自包含片段一致，回退微软雅黑/宋体） |
| `font.size` | 11 | 图内文字基线（≥11pt，样式统一规定） |
| `axes.labelsize` / `xtick.labelsize` / `ytick.labelsize` / `legend.fontsize` | 12 | 坐标轴名、刻度文字、图例文字比基线大一号 |
| `figure.dpi` / `savefig.dpi` | 300 | 出图基线（PNG 300 DPI） |
| `svg.fonttype` / `pdf.fonttype` | `none` / 42 | 可编辑 SVG/PDF 文字 |

- skill 内部绘图脚本**必须调用 `mm_style.bootstrap()` 后使用默认 rcParams**（`configure_chinese_style()` 注入），**禁止在脚本内写死字号**（`fontsize=`/`labelsize=` 显式值）——轴名、刻度、图例、标题、正文标注一律吃 rcParams 默认，需要相对缩放处按 `plt.rcParams["font.size"]` 比例引用。
- **唯一缩放例外**：密集小格布局与图中内嵌表格——
  - 相关矩阵/多面板小图等格内点缀（格内数值、显著性星号、每格轴名与刻度）：`rcParams["font.size"] × 0.75`（≈8.25pt @11）；
  - 图内嵌指标表文字：`rcParams["font.size"] × 0.85`。
  - 仅限格内/表内点缀；全图级标题、坐标轴名、图例、刻度、正文标注一律用 rcParams 默认。
- **禁止**在脚本内另设 `font.sans-serif` 把 `Arial` 排在其首位之前，否则中文被 Arial 抢占变方块；`SimHei` 必须存于首部（与正文 `paper_format.set_run_font('宋体')` 区分，图内统一黑体基线）。
- PNG 内嵌字体 docx 层不可见，validator 无法反查像素字体；故中文字体靠**生成层默认兜底**，不进 validator 硬闸门（脚本字体只到 W5 软闸，见 §3）。

## 1. 配置约束：同一张图片不得被重复写入硬闸门

- 每张登记的图片（`results/图片/*.png`）在硬闸门体系中**只对应唯一一个质量归属**，检查项不重复扫描同一对象：
  - 单图自身质量（dpi、中文字体、无遮挡、题注存在）→ 生成层工具（`validate_figure.py` / `audit_figures.py`）；
  - 图是否登记、是否插入正文、哈希一致性 → docx 层登记对账（§2）；按 sha256 单次计账，不重复计罚。
- 一张图只写一次硬闸门。禁止把同一"图 N"同时塞进多个检查项导致重复判定/重复报错。

## 2. 图表硬闸门（error 级，任一不过拒存）

下表逐条对应 `structure_validation.py` 实现（代码为真源，判法与实现一致）；只列图表相关项。

| ID | 检查项 | 机器判法 | 说明 |
|----|--------|----------|------|
| H13 | 题注格式统一（图/表） | 题注样式段（CAPTION_STYLE）文本匹配 `^[图表]\s*\d+` 但数字后未接分隔符 `：`/`:`/空格 → error（`_caption_format_issues`） | 题注须为 `图N：`/`图N `/`表N：` 式（图题下、表题上）；只查题注样式段，不误伤正文引用句 |
| — | 图片文件名规范 | `results/图片/` 下栅格图（png/jpg/jpeg/tif/tiff/bmp）文件名违反细则 → error（`_figure_filename_issues`）；违规含：以「图N」开头、描述含白名单（通用缩写白名单真源为 `structure_validation._ALLOWED_FILENAME_TOKENS`，如 RMSE/MAE/R²/AUC/F1 等）之外的非中文片段、序号缺失/重复。**完整命名细则唯一权威见 `文档/样式统一规定.md` §六，此处不重复** | 图号只写题注，防编号脱节 |
| — | `results/图片/` 图必须都用 | 目录内每张图 sha256 必须出现在 DOCX 内嵌图中，否则「未插入正文」error（`_result_figure_issues`） | 防止登记图只留目录 |
| — | 登记图 ↔ 正文对账 | `run_manifest.json` `figures` 逐条：路径存在/属 `results/`/sha256 与清单一致/修改时间在运行区间/来源脚本登记；同路径同内容不得重复登记；感知哈希与清单一致且与同批图不高度相似；清单中图必须已插入 DOCX、DOCX 不得含未登记图；DOCX 内同图不得重复嵌入（`_manifest_figure_issues` + `_manifest_checked_file`） | 真实运行结果，禁编造 |
| — | 分章图表配额 | 「模型建立与求解」章 ≥1 幅结果图（`图N` 题注）；「模型检验与分析」章 ≥1 幅检验图 + ≥1 张检验表（`_section_figure_issues`） | 结果图按论证需要分布，禁凑数 |
| — | 检验类图必须落在检验章 | 题注或图片段文字含 灵敏度/敏感/误差/稳健/鲁棒/检验 任一关键词的图，插入位置必须在「模型检验与分析」章内（`_check_figure_placement_issues`） | 图与论证位置一致 |
| — | 图片防固定值行距裁剪 | 段落行距解析为固定值（EXACTLY）且含图片 → error，图段必须用多倍行距（如 1.25/1.5）（`_clipped_object_issues`） | Word 固定值行距按行高裁剪图片，只露一条 |
| — | 图/表题注编号与引用 | 题注编号 1..N 完整（不缺失/不跳跃/无多余）；每个题注编号都须在正文被引用；题注按出现顺序递增（`_numbered_object_issues(kind='图'/'表')`） | 附录图表不纳入结构检验口径 |

- 图/表/流程图数量下限（`CUMCM_MIN_FIGURES` / `CUMCM_MIN_TABLES` / `CUMCM_MIN_FLOWCHARTS` 等）由 `contest_profile.py` 单一来源、数量闸门强制执行。
- 摘要不得插图（见 `摘要写作范式.md`）。
- **附录图表不纳入结构检验**：图/表数量、题注编号与正文引用、等效页数折算均只统计参考文献/附录之前的正文（口径统一见《文档/论文写作.md》）。

## 3. 图表 warning 级软闸门（warning 不阻断交付）

下表为 `structure_validation._soft_quality_warnings` 接线中的图表相关项（编号与代码注释链一致）；文字类 W（公式解释/查重/数据文件/章节预算/模型评价）不在此登记。

| ID | 检查项 | 机器判法 | 说明 |
|----|--------|----------|------|
| W1 | 结果分析不重复插图 | 题注匹配 `^图\s*(\d+)`，同图号计数 >1 → warning | 防止同图换题注复用 |
| W3 | 流程图题注不笼统 | 题注整句只含"流程图/技术路线/研究思路"字样（无本题内容）→ warning | 题注须体现本题内容 |
| W4 | 公式用 OMML 非图片 | 题注以 `图N` 开头且含"公式/equation"字样 → warning | 公式用 Word 原生 OMML，禁截图 |
| W5 | 出图中文正常（SimHei 打头） | `code/*.py` 含 `font.sans-serif` 且名单内无任一 CJK 字体（SimHei/SimSun/NSimSun/KaiTi/FangSong/宋体/Microsoft YaHei/微软雅黑）→ warning | 生成层 `mm_style.py` 默认已兜底，validator 难查 PNG 内字体 |
| W6 | 出图经典坑（对照 `tools/figure/references/画图避坑清单.md` P2/P3/P14/P20） | `code/*.py` 命中 `twinx(` / `.pie(` / `projection='3d'` / `cmap=jet\|rainbow\|hsv\|nipy_spectral` / `loc='best'`，或 `legend()` 未给 `loc`/`bbox_to_anchor` → warning | W 级不拒存，但须人工确认或改写 |
| W9 | 图表引出 | 题注（`图/表N` 开头且 ≤25 字）前最近文字段缺失或为标题/上一图表 → warning | 先一行说明展示什么、为何出现 |
| W10 | 图表上下文 | 题注样式段前非正文引导段、或后无 ≥15 字实质解释 → warning | 先引出、再图表、后解释，禁连续堆图 |

## 4. 落地状态

- 绘图层：
  - `tools/figure/runtime/mm_style.py`：rcParams 单一来源（§0），统一中文字体、可编辑 SVG/PDF 文字、PNG 300 DPI 和出版级 helper；模板与 helper 一律复用其默认，不另写字号。
  - 出图前静态预检：`python tools/figure/runtime/validate_figure.py <绘图脚本.py>`。
  - PDF 交付前字号审计：`python tools/figure/runtime/audit_pdf_text.py <图件.pdf>`（对引用入口经 mm_style 的图，检查文字尺寸；低于规范允许下限 ≈8.25pt（基线 11 的唯一缩放例外 0.75×）的片段即报警）。
- docx 层：§2 图表硬闸门、§3 图表 W 闸门全部编入 `structure_validation.py` 并接线；error 项由 `save_document` 拒存，W 项由 `_soft_quality_warnings` 统一加 `预警：` 前缀仅提示。
- 同图不重复约束（§1）：每张图在 docx 层只由登记对账闸门按 sha256 计一次账；单图质量由生成层工具判定，不重复计罚。

## 5. 图表分类管理（诊断图永不进正文）

> 对应 `文档/七轮自审框架.md` 第 5–7 轮。每张图在产出时按用途打类别标签，写入 `results/图片清单.md`；只有「论文用」图进入正文，诊断图绝不混入。

### 5.1 四类图表

| 类别 | 用途 | 是否进正文 | 硬性要求 |
|------|------|-----------|---------|
| **诊断型** | 调试中间态、数据清洗前后对比草稿、字体渲染诊断、异常值检查 | 否，永不进正文 | 仅用于开发期自查，不进 `results/图片/` 论文批次 |
| **对比型** | 展示方案/模型/参数对比，须含基线或参照对象 | 可选 | 必须含基线或参照对象，否则退化为诊断图 |
| **论文用** | 进入论文正文、支撑关键结论 | 是 | 通过视觉渲染验证（字号按 §0 基线、dpi≥300、中文标签、无遮挡） |
| **附录用** | 大篇幅中间结果、完整参数表、补充图表 | 仅附录 | 随附录打包，不占用正文图表闸门 |

### 5.2 管理流程

1. 出图时在脚本注释或 `results/图片清单.md` 中标注类别（`diagnostic` / `comparison` / `paper` / `appendix`）。
2. 诊断图仅留在开发目录，**不登记进 `run_manifest.json` 的 `figures`**；`result_contract.write_run_manifest` 只接受 `results/` 下论文批次图。
3. `structure_validation` 对 `run_manifest.figures` 内每张图做存在性/哈希/题注核对（§2）——诊断图不在登记批次，天然被排除在正文之外。
4. 对比型图进正文前，先确认其已含基线/参照对象。

### 5.3 与硬闸门的关系

图表分类是**写作纪律 + 登记纪律**，机器层面有两道闭环：

1. **登记图必须进正文**：`run_manifest.figures` 登记图须在论文中找到且哈希一致，否则报「登记图未插入/哈希不符」。
2. **`results/图片/` 图必须都用**：该目录下所有图都须嵌入论文，否则报「results/图片/ 中未插入正文的图片」。

因此**诊断图应只留在开发目录，不放入 `results/图片/`、不登记进 `run_manifest.figures`**；一旦误放入 `results/图片/` 或误登记，闸门会因「未插入正文」而拒绝交付。分类标签由作者在 `results/图片清单.md` 标注、评审时人工核对；该 md 为作者临时记录文件，不列入交付契约。
