# 模块四 · 论文评审与分析规范（`results/论文评审与分析.md`）

> **用途**：模拟竞赛评委打分、找风险、提修改建议（评分锚点/创新识别/报告骨架）。
> **依赖**：`知识库/评审增强/国赛评审标准.md`、`知识库/写作增强/七轮自审框架.md`
> **被引**：`SKILL.md`

评审角色模拟**竞赛评委**，按本规范规定的交付硬闸门与软规则给论文打分、找风险、提修改建议。这是交付前最后一道关，必须客观、尖锐、可操作。

> 本文定义**怎么评、输出什么**（流程与契约）。维度定义、评分锚点、创新性识别清单、类型化调整等可查表的硬规则，全部在 `知识库/评审增强/国赛评审标准.md`，本文不重复，只在使用处引用。

## 〇、红线（不可违反，贯穿全程）

1. **不编造内容**：所有评分与意见必须基于论文实际内容，不得凭空捏造数据、假设或结论。
2. **不做二元判决**：不输出"这篇一定 / 不能拿国奖"的判定，只给达标程度分析与差距描述——最终获奖由评审委员会综合决定。
3. **引用分层核验**：书目信息准确不等于观点得到文献支持。评审先核对文献著录与正文编号，再核对正文引用的具体方法、数据或结论是否能回到原文；`citation_ready=true` 不能替代观点核验。
4. **区分事实与观点**：格式问题是事实性（对错明确），论证质量是观点性（须给依据）。
5. **输入校验**：扫描版 PDF 须停止评审并提示用户，不得强行产出空洞报告。

## 一、评审前置：论文类型识别（四分法）

评分前**必须先判定论文类型**，否则后续格式/结果/创造性维度都可能出现系统性误判。按"结果呈现方式优先 → 问题领域 → 方法本质"三步决策树判定（详见 `知识库/评审增强/国赛评审标准.md` 第五章）：

- **A 传统建模型**：结果呈最优解/策略/决策方案（运筹、调度、博弈、物理过程）。
- **B 数据分析型**：结果呈统计图表/相关系数/显著性（商业数据、社会调查）。
- **C 机器学习型**：结果呈准确率/F1/AUC/混淆矩阵（训练–测试–预测范式）。
- **D 工程/信号型**：结果呈工程参数/星座图/波形/频谱（通信、雷达、信号、图像处理）。

跨学科论文按**结果呈现方式**优先归类。⚠️ **D 类"图表多 / 术语多 / 文献少"是领域特征，不扣分**（见细则第五章）。类型化纪律：不对 C 类因"图少"扣分、不对 D 类因"图多/术语多"扣分；参考文献须 8–12 篇（交付硬闸门，见细则第五章 5.4）。识别结果须写入评审报告的"基本信息"，并贯穿后续所有评分。

## 二、强制输出结构（含输出模板）

评审产物必须包含以下三段，顺序不可颠倒；报告文件按文末"输出模板"的骨架产出。详细评分锚点见细则库。

### 1. 模拟评委评分

分两步，先体检、再打分，每分必附理由（引用论文章节/公式/图表/数据）。

**1.1 格式规范审核（六维度）**
逐项检查并逐条记录：`维度 → 问题描述 → 位置（章节/页码/行号）→ 严重程度（致命/一般/轻微）→ 修复建议`。
六个维度为：① 标题与段落　② 图表编号　③ 公式规范　④ 参考文献（GB/T 7714、正文对应关系和观点证据）　⑤ 摘要规范　⑥ 页面规范。
（维度定义与严重度换算见 `知识库/评审增强/国赛评审标准.md` 第二章）

**1.2 内容质量打分（五维度带权重）**
五大维度与权重（20/25/25/15/15）及评分要点**唯一权威见 `知识库/评审增强/国赛评审标准.md` §三**，此处不重复表格。

**铁律**：每一分都须附"评分理由"且引用论文具体内容；"建模创造性"维度还须标注**置信度（高/中/低）**。

**1.3 建模创造性（必走创新识别，不得省略）**
评分前按 `知识库/评审增强/国赛评审标准.md` 第四章执行：
- 先对照**五类超额创新**（自创算法 / 跨领域融合 / 经典方法突破改进 / 建模视角创新 / 多方法协同）；
- 再勾选**七项信号清单 S1–S7**（针对性、动机说明、方法组合、改进点明确、验证支撑、自创命名、结果优越）；
- 给出**置信度**（高/中/低）；命中自创命名 S6 但看不懂、或跨领域融合无判断依据时，给保守下限分并**强制触发人工复核建议**，不得直接压低。
- 区分"国二扎实组合（16–18）"与"国一超额创新（19–20）"：无突破标志（无文献先例 / 针对赛题特殊结构自创 / 跨领域合理融合 / 结果显著优越）不得超 18；开创性建模无文献先例恰是突破硬标志，不得压分。

**1.4 P0/P1 证据检查**

- **P0 证据链**：核心结论是否回到题目条件、公式、结果文件、图表或可复现实验；强表述是否有对应证据；图表是否在正文中完成"展示对象—趋势/差异—原因或边界—意义"解释。
- **P0 引用链**：书目信息是否准确，正文编号是否对应，引用的具体方法/数据/结论是否能在原文定位；不得把标题、摘要或 `citation_ready=true` 当作观点证据。
- **P1 模型决策**：模型或算法是否说明本题适配理由；存在合理候选时是否在同数据、同指标、同约束下比较；不存在时不因形式要求制造第二个模型。
- **P1 求解透明**：关键参数、停止条件、收敛/可行性证据和失败处理是否来自真实运行记录；没有记录不得补写"团队尝试过程"。
- **P1 问题主线**：每个 5.x 分支是否写清解决的子问题、输入、输出和对后续步骤的作用；章节标题可内容化，但不破坏项目规定的一级结构。
- **P1 摘要一致性**：摘要中的方法、关键数值、创新和边界是否都能在正文与结果文件中找到对应；没有对应证据不得补写。
- **P1 表述质量**：去模板化不得依靠强行加入"我们"、情绪或虚构试错；应优先使用具体对象、数字、对比、因果条件和适用边界。

### 2. 存在风险

逐条列出可能**导致丢分甚至取消评奖**的风险，并给严重度（高/中/低）：
- 模型假设风险（假设过强/不成立/写了不用）。
- 数据不足风险（样本少、缺失、代表性差）。
- 算法复杂度 / 可复现风险（缺源码、结果不可重跑）。
- 创新不足风险（套用常规、无针对性处理）。
- 引用证据风险（书目信息正确但正文观点未被原文支持、引用与正文脱节）。
- 合规风险（匿名失败、格式/源码缺失、身份信息披露）。

### 3. 修改建议

针对每条风险与评分短板，给出**具体、可落地**的改动，按优先级排序，每条必须指向论文**具体位置与具体改动**，绝不说"多查文献"这类空话：

- **P0（必须改）**：致命级问题、高风险项、合规红线——不改正将直接丢分或取消评奖。
- **P1（建议改）**：一般级问题、明显拉低评分的短板——改正可显著提升获奖概率。
- **P2（可选优化）**：轻微瑕疵、锦上添花项——有余力时优化。

## 三、使用方式（保留原定位）

- Step 9 生成本文件；依据"修改建议"**回改 `完整论文.docx`**（必要时回改 `results/论文评审与分析.md` 与 `code/`）。
- 审核摘要、结论和主图时，核对当前批次 `results/`、`results/run_manifest.json` 和 `results/论文评审与分析.md`；数值、单位、来源脚本或场景不一致时至少列为 P1。
- 循环直到评分达"优秀"档、高风险项清零、合规全过。
- 本文件本身**不计入**交付契约外的多余文件——它正是契约要求产物之一。

## 四、代码层审计（三仓库借鉴，可选执行）

> 以下审计模块为代码层自动化工具，评审时可调用以补充人工评审。来源：mathmodel-skill（per-Qi 评分）、MathModeling-skills（三层审计/冻结数字）、MathModelAgent（9 步验收）。

| 审计模块 | 文件 | 职责 | 调用方式 |
|---------|------|------|---------|
| 冻结数字一致性审计 | `tools/project_ops/consistency_audit.py` | 论文中每个数字必须存在于 `run_manifest.json`，冲突即阻塞 | `audit_consistency(docx_path, manifest_path)` |
| per-Qi 独立评分 | `tools/project_ops/per_qi_scoring.py` | 每个子问题独立评分，输出 verdict（pass/refine_partial/refine_full） | `score_qi(qi_id, dim_scores)` |
| 三层独立审计 | `tools/project_ops/three_layer_audit.py` | consistency → completeness → quality-assurance，任一失败不可提交 | `run_three_layer_audit(project_root, docx_path, manifest_path)` |
| 9 步自动验收 | `tools/project_ops/nine_step_verification.py` | 12 项硬错误 + 7 项警告，默认只输出 stdout 摘要与 exit code（瘦身不落盘；显式传 `write_report=True` 才写报告） | `run_verification(project_root, docx_path, manifest_path)` |

**审计结果处理**：
- 冻结数字审计发现冲突 → 列为 P0 必须改
- per-Qi 评分 verdict 为 `refine_full` → 列为 P0 必须改
- 三层审计任一失败 → 论文不可提交
- 9 步验收硬错误 → 列为 P0 必须改，警告 → 列为 P2 可选优化
