# 论文合规与交付前自审规范

> 本文件是论文写作阶段的唯一执行规范。`知识库/写作增强/七轮自审框架.md` 仅保留解释、案例和扩展清单；若内容冲突，以本文件、校验器和竞赛当届官方文件为准。

## 一、交付阻塞项

以下问题未修复，不得进入最终交付：

- 摘要没有定量结果；
- 符号在使用前未定义；
- 论文数字、图表或结论无法追溯到 `results/run_manifest.json`；
- 只报告数字而没有对象、对比、原因或边界解释；
- AI 使用声明缺失、位置错误或与真实使用情况不符；
- 机器校验器报告致命错误。

软性写作建议只进入 `results/论文评审与分析.md`，不改变机器硬闸门。

## 二、AI 工具使用声明

论文必须在参考文献之前放置以下二选一声明，并以当届竞赛官方文件为最终依据：

- 未使用：`本参赛队在竞赛过程中未使用任何AI工具。`
- 使用：`本参赛队在竞赛过程中使用了AI工具，主要用于【简要用途，如语言润色、代码调试等】，详细使用情况见支撑材料。`

声明必须真实。使用 AI 时，参赛队应按当届官方要求准备支撑材料；本项目不虚构、不自动生成未发生的使用记录，也不强制生成官方未要求的额外文件。

## 三、最小自审顺序

1. **证据链**：每个关键数字、图表和结论都能回到题目条件、公式推导、运行结果或真实文献。
2. **结果一致性**：逐位核对论文、图表、`results/数据/` 和 `run_manifest.json` 的数值、单位、时间范围和场景。
3. **模型适配性**：检查变量、约束、目标、数据结构与模型是否匹配；不要按题型直接套算法。
4. **结果解释**：每个核心结果至少有对象、对比、原因或边界中的一项解释。
5. **合规与机器校验**：运行 `self_check.py`、项目审计和终态论文校验，依据 exit code 和报告处理问题。

时间有限时，优先完成上述五项和机器报告的全部阻塞项，再做风格润色、扩展图表和可选模型比较。
