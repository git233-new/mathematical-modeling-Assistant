# 质检清单

> **用途**：组装或提交论文前的终检清单（passed / passed_with_warnings / failed 三态判定）。
> **依赖**：`知识库/写作增强/七轮自审框架.md`
> **被引**：`SKILL.md`

## 最终判定

采用三种质检状态:

- `passed`:允许最终组装
- `passed_with_warnings`:允许最终组装,但局限性应保持可见
- `failed`:阻止最终组装

若有任何必答子问题未作答,则质检失败。

## 工作流完整性(所有 Qx 必须通过)

对每个子问题,检查:

- [ ] 合并分析与结果文件存在(`results/论文评审与分析.md`)
- [ ] 分层方法卡模板已并入 `知识库/方法库/设计原则.md` 文末附录
- [ ] 人工决策台账存在(`results/论文评审与分析.md` 或评审文件)
- [ ] 风险探针摘要存在(`results/论文评审与分析.md`)
- [ ] 最终结果清单存在(`results/run_manifest.json`)
- [ ] 论文关键数值与清单登记一致
- [ ] 最终方法说明存在(`知识库/方法库`)  ← 规则 1
- [ ] 最终结果分析存在(`results/论文评审与分析.md`)  ← 规则 2
- [ ] 稳健性/敏感性/极限情形检查存在(`results/论文评审与分析.md`)或已说明例外
- [ ] 图-表规划存在(`文档/论文写作.md` 的图表计划)

## 问题覆盖度

检查:

- 所有原始子问题均已列出
- 每个子问题都有对应的回答
- 每个回答都有模型、结果或已说明的非建模回应
- 子问题间的依赖已处理
- 最终结论回映到原始问题

阻塞问题:

- 子问题缺失
- 子问题理解错误
- 结论未能回答所问的问题

## 方法一致性

检查:

- 任务类型与所选方法匹配
- 论文中的方法描述与最终方法说明及已批准的方法卡片一致
- 每个主模型都有基线(除非已说明)
- 条件备选方案处于休眠,除非其记录的触发条件已发生
- 被淘汰的方法有恰当提及
- 被否决的方法未在其后被描述为"已采用"
- 用户提供的建模思路、假设和求解路线为主方案,未经用户同意不得替换或扩展(见 SKILL.md"用户建模思路优先")

阻塞问题:

- 论文描述的方法与最终方法说明不符
- 主模型无基线且无说明
- 方法无法产出要求的输出

## 数据一致性

> 内容自查详见 `知识库/建模增强/证据可复现审计.md`（三态/泄漏清单）；本节只保留终检项。

检查:

- 赛题附件数据(CSV/XLSX/PDF 内表格)已真读真用,未被忽略或编造
- 原始数据未被改动
- 清洗数据已留档
- 字段含义与单位清晰
- 缺失值与异常值已处理或已讨论
- 脚本中使用的数据与规范化数据画像一致
- 衍生特征已解释

阻塞问题:

- 必需数据字段缺失
- 原始数据被覆盖
- 未留档的清洗改动实质性地改变了结果
- 单位不一致影响解读
- 凭空编造或"示意性"伪造数据

## 代码与结果一致性

检查:

- 脚本存在于 `code/Q<序号>.py` 等(每小问独立入口,命名 `Q<序号>.py`,子模块 `Q<序号>_<描述>.py`,共享核心算法用 `solve_common.py`,生图配置用 `viz.py`,非解答脚本不以 Q 开头、不依赖 `solve_common.py`;全 Python,与 `文档/代码规范.md` 一致)
- 运行说明可在 `requirements.txt` 与 `results/run_manifest.json` 中找到
- 输出文件遵循 `results/{图片,数据}/` 扁平结构
- 重跑覆盖当前结果,旧结果不残留混淆
- 最终结果清单 `results/run_manifest.json` 由 `tools.docx.core.result_contract.write_run_manifest()` 生成
- 论文数值与结果文件一致
- 必要时固定随机种子

阻塞问题:

- 论文中的结果在输出文件中找不到
- 代码输出与论文文字矛盾
- 脚本无法对应到任何子问题
- 运行时失败阻塞了必需结果
- 论文绕过 `run_manifest.json` 从旧目录或代码上下文抄参数

## 基线与稳健性

检查:

- 需要处已有基线结果
- 主模型已与基线对比
- 每个子问题有稳健性或灵敏度检查
- 脆弱的结论已标记
- 稳健性声称未超出已完成的检查
- 结论的边界已说明

阻塞问题:

- 无基线却声称"更优"
- 无稳健性检查却声称"稳定"
- 把计划中的稳健性检查当作已完成来呈现

## 图表

检查:

- 每个被引用的图都存在,或已明确标记为"计划中"
- 每个被引用的表都存在
- 每张图或表都有来源产物(`results/图片/`)
- 论文中的图属于论文正式图——不得误把诊断图放进论文
- 图注说明了要点
- 视觉证据支撑了相关声称
- 没有把装饰性图当作证据使用
- 图表全中文(遵循 `知识库/方法库/图表规范.md`)

阻塞问题:

- 引用了图或表却缺失
- 表中含编造的数值
- 图与结果文件矛盾
- 视觉呈现夸大了证据

## 论文写作

> 本节为机器闸门视角的终检；逐项内容自查以 `文档/论文写作.md` 为准，定稿后审查以 `知识库/写作增强/七轮自审框架.md` 第 5–7 轮为准。

检查:

- 假设确属必要且与建模需求相关联
- 符号先定义后使用,并与全局符号表一致
- 方程与变量、单位匹配
- 数值声称有产物支撑
- 方法描述与最终方法说明一致(而非候选池)
- 结果来自最终结果分析(而非原始实验输出)
- 已包含局限性
- 结论未引入新声称
- 摘要未夸大结果
- 每个 5.x 分支在第五章内完成正式、清晰的结果解释闭环;小标题按内容自拟,不得机械套 `模型建立/模型求解/结果分析`,也不得另起与"模型建立与求解"并列的一级结果分析章节

阻塞问题:

- 未经支撑的数值声称
- 编造的参考文献或结果
- 影响结论却未说明的局限性
- 结论超出证据

## 交付前硬闸门（由 `save_document` 自动执行）

**硬闸门**（任一不过即拒绝保存，详见 `文档/论文写作.md` 交付自检入口 + `文档/图片闸门配置与绘图规范.md`）：

- [ ] `validate_paper_structure()` 通过（结构、对象尺寸、估算篇幅）
- [ ] `check_black_fonts(doc)` 返回空（全文字体全黑）
- [ ] `scan_forbidden_words(doc)` 零命中（含段落+表格+附录源码）
- [ ] 正文、图、表、公式和参考文献数量达标
- [ ] 模板化表达已按 `知识库/写作增强/去AI味指南.md` 清洗

**软门**（不满足只告警，不阻断交付）：

- [ ] 摘要、关键词、分页符和正文起始结构
- [ ] 图/表编号连续且正文引用、参考文献双向对应

阻塞问题:

- 页数未达项目交付下限却调格式凑页(应补实质内容)
- 论文正文与 code/ 代码文件出现身份泄露或生成痕迹词
- 全文非黑字体(落盘前会被强制刷黑,但仍须自查写作习惯)
- 摘要溢出第 2 页或内容不足半页

## 反编造

检查:

- 无编造的数据、参考文献、结果、图表或实验
- 无编造的数值
- 无未经支撑的"更优"类声称
- 无隐藏的不确定性
- 无把装饰性图当作证据

## 产物可追溯性

对每个主要声称,至少指出一个支撑产物:

| 声称类型 | 期望产物 |
|------------|-------------------|
| 问题解读 | `results/论文评审与分析.md` 的问题解析 |
| 方法选择 | 人工决策台账 + 最终方法说明 |
| 数据陈述 | `results/数据/` 清洗与画像产物 |
| 数值结果 | `results/run_manifest.json` + `results/数据/` |
| 图表声称 | `results/图片/` 来源文件 |
| 稳健性声称 | `results/论文评审与分析.md` 下的稳健性报告 |
| 基于代码的结果 | 经审查的脚本与输出 + `results/run_manifest.json` |
| 最终结论 | 论文章节加支撑性结果 |
| 参考文献 | 正文 [1][2] 标注与文末文献对应;文献检索用 `tools/paper_search/` |

若找不到对应产物,该声称应被删除或标记为不完整。

## 修复路由

用最早能修复该问题的方法。

| 问题 | 修复方法 |
|-------|-------------|
| 问题理解错误 | `文档/论文写作.md「赛题详解与结果分析规范」` |
| 任务类型错误 | `文档/论文写作.md「赛题详解与结果分析规范」` |
| 方法不适配任务或数据 | `知识库/方法库/设计原则.md`、`模型选型决策矩阵.md` |
| 子问题间符号冲突 | `知识库/写作增强/假设与符号写作.md`（全文符号一致） |
| 假设缺失或冲突 | `知识库/方法库/设计原则.md` |
| 数据问题 | `tools/xlsx/`、`tools/pdf/`、`文档/代码规范.md` |
| 缺失方法说明(规则 1) | `文档/论文写作.md「赛题详解与结果分析规范」` |
| 缺失结果分析(规则 2) | `文档/代码规范.md`、`tools/docx/core/result_contract.py` |
| 缺失结果生成 | `文档/代码规范.md` |
| 代码或输出不一致 | `tools/project_ops/project_audit.py`、`文档/论文写作.md` 的交付自检入口 |
| 缺失稳健性证据 | `知识库/建模增强/证据可复现审计.md` |
| 不支持的视觉呈现 | `知识库/方法库/图表规范.md`、`tools/figure/` |
| 图表缺失或质量低 | `tools/figure/` |
| 写作不支持或不清晰 | `文档/论文写作.md`、`知识库/写作增强/` |
| 语言或过声称问题 | `知识库/写作增强/去AI味指南.md` |
| 引用未核实或编造 | `tools/paper_search/`、`知识库/写作增强/七轮自审框架.md` |
| 跨阶段多个阻塞问题 | `文档/论文评审.md`、`tools/project_ops/project_audit.py` |

## 实用原则

若质检失败,不要组装最终论文。

先修复最早的阻塞问题。
