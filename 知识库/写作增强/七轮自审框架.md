# 七轮自审框架（国赛论文·单一权威版）

> **三文件分工**：
> - **`文档/论文评审.md`（评审视角）**：模拟评委打分、找风险、提修改建议
> - **本文件（自审视角）**：作者自查七轮清单、判定标准、执行建议
> - **`文档/合规检查清单.md`（合规视角）**：交付前硬核验（匿名/文件规格/AI声明/可复现）

> 用途：论文定稿前逐轮自检，每轮聚焦一个维度。  
> 优先级：第1轮最关键（三等奖与一等奖差距），时间紧张至少完成第 1、3、5、7 轮。  
> 最终 DOCX 按 `文档/论文写作.md` 交付自检入口扫描模板化表达。

---

## 第1轮：论证逻辑（结论是否站得住）

**核心工具：主张—推理—结果核对**

| # | 主张 | 推理或结果来源 | 类型 | 状态 |
|---|---|---|---|---|
| 1 | 核心结论 | 对应公式/结果表/运行输出 | main | ✅/⚠️/❌ |
| 2 | 模型 X 优于 Y | 同数据同指标可比条件下的对照 | comparison |  |
| 3 | 对 λ 不敏感 | 灵敏度曲线（λ扫 0.01→1.0，输出波动<3%） | sensitivity |  |

**需额外检查的主张类型**：

| 类型 | 含义 | 需要检查 |
|---|---|---|
| `comparison` | 某模型/方法优于另一种 | 同数据、同指标、可比条件下的对照 |
| `mechanism` | 某因果/作用机制 | 推导/机理条件/专门实验；相关≠因果 |
| `sensitivity` | 参数不敏感/假设合理 | 题目确有需要时做扰动或极限检查 |
| `boundary` | 模型适用范围/局限 | 说明已检查边界和未覆盖情形 |
| `innovation` | 本题化改进点 | 说明新增内容及实际影响，不套用案例表述 |

**措辞判定**：✅可保留、⚠️改成"在本题数据/条件下"、❌删除或补算

**常见漏洞**：
- [ ] 悬空主张（无题目条件/推导/结果来源）→ 删/改/补算
- [ ] 一图撑多结论 → 拆分解释或收窄结论
- [ ] 跳跃逻辑（A→C缺B）→ 补中间步骤
- [ ] 循环论证（用结论证结论）→ 重组路径，引入独立证据
- [ ] 稻草人（基准太弱）→ 选公认强基准重对比

**反方测试**：对每核心结论问"哪些条件下不成立"，无法回答则补边界或弱化结论。

**通过条件**：无明显跳步、循环论证、超出结果范围的强断言。

**证据分层**：书目信息层（作者/年份/期刊/DOI）≠ 观点证据层（文献是否真提出该方法/报告该结果/支持该条件）。`citation_ready=true` 只过书目层；正文引用具体方法/结论/因果/创新时必须另核原文。找不到对应内容 → 删观点/改弱表述/换有证据来源。

## 第2轮：骨架完整性（结构齐不全）

**摘要六要素**：背景/缺口/方法/结果（每子问有具体数值）/意义/边界 + 数值可对应正文

**问题分析**：
- [ ] 场景与数据规模
- [ ] 每子问题核心困难
- [ ] 合理替代方案给出选择理由（单一自然模型不强造替代）
- [ ] 外部方法/参数有真实文献或题目条件来源
- [ ] 多问有数据流/决策链/递进 → 用流程图（图1）表达
- [ ] 每章说明输入/输出/对后续作用，无只为填模板的章节/过渡句

**建模求解**：
- [ ] 每节开头说明"解决什么"
- [ ] 说明模型为何适配；有合理候选交代取舍，无则不强造比较
- [ ] 有合理候选 → 同数据同指标同约束比较；无 → 说明不强造对比
- [ ] 求解参数/停止条件/收敛/可行性证据来自真实运行记录
- [ ] 公式从问题推导（非抄教科书标准形式）
- [ ] 每参数含义与取值依据说明
- [ ] 有算法伪代码或流程图
- [ ] 按证据需用图表呈现结果
- [ ] 每图表后自然地介绍图表内容并给出简单解释；不能只写“由图可知”
- [ ] 每子问题有相称的误差/可行性/极限/基线/灵敏度检查

**模型评价**：
- [ ] 创新点一句话概括
- [ ] 局限针对本模型具体选择（非万能句）
- [ ] 改进具体可操作（非"将进一步研究"）

**骨架齐全**（对齐国奖范式）：
- [ ] 顺序正确：重述/分析/假设/符号/建模求解/检验/评价/文献/附录
- [ ] 第五章各 5.x 分支按内容自拟小标题，完成"模型/算法—求解证据—结果解释"闭环，未机械套"建立→求解→结果分析"或另起一级结果章节
- [ ] 无重复内容

**通过条件**：六要素齐全、骨架无缺、各子问题结构一致、无重大重复。

## 第3轮：表达质量（去 AI 味）

**配合 `去AI味指南.md` 逐条清洗**

**AI 味扫描**：
- [ ] 标志着/重要作用/重要意义等过度强调词
- [ ] 突破性/令人震撼等广告词
- [ ] 不仅……而且……平行结构
- [ ] 专家认为/研究表明无引用
- [ ] 连接词机械成串、无真实逻辑（不以单词出现次数判定）
- [ ] 深入探讨/充分展示/具有重要意义
- [ ] 强行三法则（原因有三）
- [ ] 同义词循环（模型/算法/方法/方案来回切换）
- [ ] 公式化"挑战与展望"结尾
- [ ] 过度破折号（——）
- [ ] 无数据支撑的空泛积极结论

**数据与符号一致性**：
- [ ] 所有数值摘要/正文/图表一致
- [ ] 单位正确
- [ ] 公式用途/符号定义/前置说明一致；无手工编号或失配引用
- [ ] 图表编号与正文引用一致、全局连续无跳号
- [ ] 参考文献编号与正文引用一致
- [ ] 每条引用书目信息准确；正文借用具体方法/结论能在原文定位；`citation_ready` 未被错当观点证明
- [ ] 同指标精度统一（百分比统一保留1位小数）
- [ ] 符号表内符号与正文完全一致（无正文用 a 表内写 α）

**术语与概念一致性**：
- [ ] 同一概念全文固定一词
- [ ] 模型命名统一（如"XGBoost 模型"不中途变"XGBoost 算法"）
- [ ] 专业术语准确（参照 `文档/论文写作.md §四`（题型画像）与各方法库）

**通过条件**：AI 味清单全清、数值/编号/符号三处一致、术语固定。

## 第4轮：格式规范

**按 `文档/论文写作.md` 项目交付下限逐项核对**

**通用**：
- [ ] A4、边距≥2.5cm、左侧装订、首页摘要、无身份信息
- [ ] 正文宋体小四、固定行距18磅、首行缩进2字符；标题黑体（数值唯一权威：`文档/样式统一规定.md`）
- [ ] 数字/公式用 Times New Roman / 斜体变量
- [ ] 页码首页到末页均存、页脚居中、阿拉伯数字从1连续
- [ ] 正文页数符合 `文档/论文写作.md` 交付下限表

**图表**：
- [ ] 图标题图下居中"图 N xxx"，编号全局连续无缺号
- [ ] 正文表格三线表、表头黑体、数字右对齐；**附录表格用闭合方框表（四边外框、无内部竖线），禁用三线表**；**附录图表不纳入正文结构检验**（图/表制计数、题注编号与正文引用均只针对参考文献之前的正文，详见《文档/论文写作.md》）
- [ ] 每图服务论证（几何/曲线/流程/方位各司其职）
- [ ] 图中中文正常（出图前注册字体如 SimHei）

**公式**：
- [ ] OMML 原生、居中、上下间距 27pt、上一行有解释

**参考文献**：
- [ ] GB/T 7714 格式一致、编号按出现顺序、每条正文有标注
- [ ] 书目信息准确，正文引用具体方法/结论能在原文定位
- [ ] 无 CSDN/知乎/百度百科等非学术来源；AI 工具登记遵从 `文档/合规检查清单.md 附录 A`
- [ ] 来源与题目相称；不凑数量强行加近年文献，不把案例卡/标题/摘要当原文证据

**附录与源码**：
- [ ] 含全部可运行源码 + 支撑材料列表
- [ ] 源码变量名与论文符号一致、分节注释对应各子问题
- [ ] 源码运行结果与论文数据严格一致

**通过条件**：以上格式项全部达标，无格式违规。

## 第5轮：数据与结果一致性

**目标**：确保论文所有数据、图表、结论与 `results/` 真实运行结果一致。

- [ ] 论文引用数值均可在 `results/数据/` 找到对应文件
- [ ] 论文插入图片均可在 `results/图片/` 找到对应文件
- [ ] `run_manifest.json` 图片哈希与论文实际插入图一致
- [ ] 论文关键数值与 `results/论文评审与分析.md` 一致
- [ ] 敏感性分析参数范围与代码实际范围一致
- [ ] 对比实验基线结果与代码输出一致

**常见错误**：论文写"最优解 1234.56"代码输出 1234.57；图片文件名与 manifest 不一致；敏感性表格数值与代码对不上。

## 第6轮：评审视角预演

**目标**：以国赛评委视角识别可能被扣分的关键问题。

- [ ] 明确说明模型假设及合理性
- [ ] 模型建立有清晰数学推导，非直接给结论
- [ ] 结果分析含合理性讨论
- [ ] 有模型检验（残差/拟合优度/交叉验证等）
- [ ] 有敏感性/稳定性分析
- [ ] 优缺点客观，非只说优点
- [ ] 参考文献规范、引用恰当
- [ ] 摘要 3 分钟让评委读懂核心贡献

**风险分级**：

| 等级 | 典型问题 | 处理 |
|---|---|---|
| P0（致命） | 数据造假、模型不匹配、结论矛盾 | 必须修改 |
| P1（严重） | 缺模型检验、敏感性缺失、假设不合理 | 强烈建议修改 |
| P2（一般） | 表达不精炼、图表标注不清、参考文献格式 | 有时间则修改 |

| ⚠️ 有条件通过 | 仅非关键项有问题 → 标注后交付 |

## 执行建议

1. **时间**：每轮 15–30 分钟，总计 2–3.5 小时
2. **顺序**：严格 1→7，不跳轮
3. **记录**：问题记在 `results/论文评审与分析.md`
4. **闭环**：发现问题立即修改，修改后重跑该轮
5. **终检**：第七轮后再快速浏览全文确认无遗漏
6. **最小可行**：时间有限至少完成第 1、3、5、7 轮

> 建议：每轮发现问题先修复完再进下一轮，避免交叉修改引入新问题。

## A 摘要（5 项）

| 编号 | 反模式 | 检查方法 | 修复方向 | **正向模式** |
|---|---|---|---|---|
| A1 | 摘要无定量结果 | 摘要是否至少含一个带单位/百分比的数字 | 补充核心数值结果 | **模式 1**：摘要同时回答五件事——问题/约束 → 方法 → 数值结果 → 验证 → 边界 |
| A2 | 摘要信息混乱 | 是否按"问题→方法→结果→验证→边界"顺序 | 重排为五段式 | **模式 1**：摘要是结果地图，五段式固定结构 |
| A3 | 摘要与正文不符 | 摘要数字/结论是否能在正文找到对应 | 逐条核对，不一致改摘要 | **模式 1**：摘要数值、方法名、创新、边界必须在正文与结果文件对应 |
| A4 | 关键词空泛 | 关键词是否含具体方法名/模型名/领域术语 | 替换为具体术语 | **模式 1**：关键词用领域+方法组合（如"骑手调度；0-1指派；改进遗传算法"） |
| A5 | 摘要过长/过短 | 字数是否在 700-800 字、单独成页 | 精简或补充 | **模式 1**：700-800 字，单独占第 1 页 |

## 使用方式

1. **终审对照**：七轮自审第七轮时逐条对照，命中项记录编号
2. **L1 Critic 引用**：评分反馈直接引用反模式编号（如"命中 A1、C4"）
3. **修复闭环**：每条命中项修复后，在 `results/论文评审与分析.md` 记录修复情况
4. **阻塞规则**：A1（摘要无定量结果）、B6（符号未定义先出现）、D1（代码无追溯）、E1（只报数字不解读）为阻塞项，未修复不得提交
