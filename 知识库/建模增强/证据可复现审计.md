# 证据可复现审计（Evidence & Reproducibility Audit）

> 定位：保证论文里的**每一个重要结论**都能追溯到可核验的证据，且所有数值可在 `results/` 中复现。
> 红线：对齐 `文档/论文写作.md §八`——「结果必须结合真实运行结果，数值来自 results/，不得编造」。
> 适用：国赛（CUMCM）论文所有模型、结果、图表、结论，尤其是冲刺国奖时评委对「数据真实性」的零容忍。

---

## 1. 核心原则

1. **结论皆可溯**：任何进入论文的结论（数值、排序、趋势、显著性），必须能指向一条证据（数据/代码/结果表/图/公式/文献）。
2. **数值可复现**：给定同环境 + 同随机种子 + 同输入，重跑代码应得到一致（或统计一致）的结果。
3. **三态分明**：探索结果、验证结果、最终冻结结果必须分开管理，禁止把探索期的中间值写进正式结论。
4. **如实报告**：不确定性、失败实验、模型失效区间、适用范围都要写，而不是只报好结果。
5. **禁止编造**：不得凭空生成数据、不得把未运行模型的「预期值」当结果、不得美化误差。

---

## 2. 证据类别与映射方式

| 证据类别 | 含义 | 在论文中如何锚定 |
|---|---|---|
| 数据 | 原始/清洗后的输入 | 注明来源附件、预处理脚本路径、行数/字段 |
| 代码 | 生成结果的脚本 | 注明脚本文件名 + 关键函数 + 提交版本 |
| 结果表 | 数值输出（CSV/Excel） | 引用 `results/数据/xxx.csv` 的具体行列 |
| 图 | 可视化结果 | 引用图号 + 数据来源文件 |
| 公式 | 解析推导/理论结果 | 注明符号定义与假设，推导链完整 |
| 文献 | 外部依据/对比基准 | 给出引用编号，结论与文献主张一致 |

**映射规则**：论文每出现一个「结论性数字」，旁边应有可追溯标记。建议写作时在 `文档/论文写作.md §八`用括号标注来源，例如：
> 示例：最终冻结冠军测试集 RMSE=0.99（见 `results/数据/nn_test_metrics.csv`，种子=42，5 次均值）。

---

## 3. 随机种子与可复现基线

### 3.1 强制固定项

所有涉及随机性的环节**必须固定种子**：

| 环节 | 固定方式（Python 示例） | 备注 |
|---|---|---|
| 数据切分 | `np.random.seed(42)` 后再 `train_test_split` | 切分种子与模型种子可不同但要记录 |
| 模型初始化 | `random_state=42` / `torch.manual_seed(42)` | NN 权重初始化、Dropout 都要固定 |
| 集成采样 | `RandomForestClassifier(random_state=42)` | Bagging 抽样依赖种子 |
| 蒙特卡洛 | `np.random.seed(42)` + 记录抽样分布参数 | 画收敛曲线确认 N 足够 |

### 3.2 环境快照

在 `results/` 或论文附录记录：
- 语言与版本（Python 3.x / MATLAB R20xx）
- 关键库版本（numpy、sklearn、torch…）
- 操作系统 / 硬件（若涉及 GPU 非确定性，注明）
- 数据快照哈希（见第 5 节）

> 目的：让三个月后、换一台机器的人也能复现你的数字。这是国奖答辩被追问时的底气。

---

## 4. 结果三态管理

| 状态 | 定义 | 何时落入 | 能否进正式论文 |
|---|---|---|---|
| **探索结果** | 调参、试跑、方法筛选期得到的数值 | 模型尚未冻结、还在 冠军—挑战者 对抗中 | 否，仅内部看 |
| **验证结果** | 在固定协议下对候选模型做公平对比的数值 | 完成公平对比、尚未最终冻结 | 仅作对比表中间行 |
| **最终冻结结果** | 最终冻结冠军在测试集/正式数据上的报告值 | 停止规则触发、冠军冻结后唯一一次报告 | **是，论文唯一采信来源** |

**铁律**：
- 论文图表/结论表里的数字，**只能是最终冻结结果**。
- 若探索期某个「好看的数字」想用，必须先把它在冻结协议下重新跑一遍确认，否则删除。
- 同一指标在探索/验证/冻结三态的数值若差异巨大，说明存在泄漏或不稳定，必须回溯整改。

## 5. 结果哈希与一致性检查

### 5.1 哈希什么

对每个关键输出文件计算哈希，写入审计表：

```bash
# 数据快照
sha256sum data/cleaned_train.csv
# 结果文件
sha256sum results/数据/nn_test_metrics.csv
# 代码版本
git rev-parse HEAD   # 若用 git；否则对脚本取哈希
```

### 5.2 一致性检查流程

1. **跨种子一致性**：NN/集成等对种子敏感模型，跑 ≥5 个种子，记录均值±标准差；若某次离群 >2σ，排查是否种子问题或数据泄漏。
2. **跨环境一致性**：在另一台机器或 clean 环境重跑冻结脚本，核对哈希/关键数值一致。
3. **数值自洽**：结果表中的分项之和应等于合计；RMSE≥MAE；R² 落在合理区间（预测 R² 不应 >0.999 除非过拟合或泄漏嫌疑）。
4. **图数一致**：图中读出的数值（如拐点坐标）应与结果表一致，禁止「手绘美化」。

### 5.3 轻量留痕

不建额外审计表。保留关键结果 CSV/JSON、对应 `code/Q<序号>_*.py` 和 `results/论文评审与分析.md` 中的结果说明即可。

## 6. 不确定性、失败与适用范围的报告

国奖论文不怕「模型有局限」，怕的是「假装没有局限」。必须主动报告：

### 6.1 不确定性
- 给出置信区间 / 预测区间（如销量预测附 95% PI）。
- 多次种子的均值±标准差。
- 蒙特卡洛输出的分位数（P5/P50/P95）。

### 6.2 失败与负面结果
- 记录未晋级的挑战者及其败因（如「SVR 在高位需求区间误差骤增」）。
- 记录尝试过但放弃的方法（如「PCA 降维后 K-Means 区分度反降，故弃用」）。
- 这反而证明你做了**真实比较**，是加分项。

### 6.3 适用范围（边界）
- 模型在哪些数据区间有效、哪些区间失效（如「BP 神经网络在外推 3 个月以上时误差放大」）。
- 假设不成立时结论如何变化（敏感性分析的落点）。

## 7. 禁止编造数据结果（红线清单）

以下行为**一律禁止**，发现即视为学术不端：

- [ ] 编造 `results/` 中不存在的数值。
- [ ] 把「预期/应该」的结果当作「已运行」结果写进论文。
- [ ] 美化误差（只报最好的一次、隐藏最差的一次而不说明）。
- [ ] 用不同数据/不同指标悄悄给某模型「加分」以制造对比优势。
- [ ] 复制文献图表伪装成本队结果。
- [ ] 把探索态的中间值当最终结论。

**发现偏差时的正确做法**：
1. 若复现不出论文数字 → 立即回退到上一个可信状态，定位泄漏/种子/数据问题。
2. 若真实结果不如预期 → 如实报告并分析原因（这仍是有效工作），绝不用假数掩盖。
3. 在 `results/论文评审与分析.md` 如实写「模型在 X 情形下误差较大，原因可能是 Y」。

## 10. 复现脚本最小模板（建议结构）

把「一键复现」作为交付物的一部分，目录约定：

```text
project/
├── code/         # Q1.py 等解答入口（Q<序号>.py）、solve_common.py 核心算法、viz.py 生图配置、build_paper.py 等非解答脚本
├── results/          # 合并分析、评审、真实结果表和图片
└── 完整论文.docx
```

脚本头部统一约定（Python 示例）：

```python
import numpy as np, random, torch, os
SEED = 42
def set_seed(s=SEED):
    random.seed(s); np.random.seed(s)
    torch.manual_seed(s); torch.cuda.manual_seed_all(s)
    os.environ["PYTHONHASHSEED"] = str(s)
set_seed()
# 训练/测试切分也要固定 seed，禁止在报告前偷偷换切分
```

> 评委或队友重跑 `code/` 应得到与论文一致的数字；若不一致，说明结果或代码存在问题。

## 11. 数据泄漏自查清单

数据泄漏是「数字好得不像真」的头号原因，提交前逐项排查：

- [ ] 测试集是否参与了标准化/归一化的统计量计算？（应只用训练集 fit）
- [ ] 特征工程是否用到了测试集信息（如未来值、标签泄漏）？
- [ ] 交叉验证是否在做特征选择/调参之后才切分？（应先切分再在训练折内选特征）
- [ ] 时间序列是否随机切分导致未来泄漏？（应按时间顺序切）
- [ ] 不平衡采样的 SMOTE 是否只作用于训练折？（测试折必须原始分布）
- [ ] 同一指标在探索/验证/冻结三态差异是否异常大？

任何一项命中，立即回退整改，并在 `results/论文评审与分析.md` 记录原因与修复。
